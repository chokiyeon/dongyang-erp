# 일부 또는 전액 지급한 거래의 취소·환급

2026-11-04 개발 기능. 회사 실거래를 변경하거나 은행 송금을 실행하지 않는다.

## 사용 순서

1. **매입·매출 → 원본 파일 검토**에서 음수 수정세금계산서가 들어 있는 XLSX를 선택한다.
2. 해당 행의 **기지급 취소·환급 검토**를 누른다. 같은 달·같은 사업자·공급가액/세액/합계 전액이 일치하는 원본 청구를 직접 확인한다.
3. 실제 은행 지급/수금액과 별도 환급 정산을 확인하고 환급 예정일·사유를 입력한다. 등록은 원본 청구를 취소하지만 원래 은행 연결·지급액을 유지한다. 미지급 잔액은 종료하고 이미 지급한 금액만 환급 예정으로 만든다. 예를 들어 110만 원 중 40만 원을 지급한 원본을 취소하면 미지급 70만 원은 종료하고 환급 예정은 40만 원이다.
4. **수정·전액취소 증빙 → 상세 → 환급 은행 거래 연결·해제**에서 실제 반대 방향 통장 거래를 선택한다. 매입 취소는 환급 입금, 매출 취소는 환급 출금이다.
5. 일부 또는 전액을 연결한다. 원본 지급일과 수정증빙일 이후의 원화 통장 거래만 사용하며 수기 환급·잔액 초과·차액 임의 완료는 허용하지 않는다. 정확한 전액 연결 시에만 완료된다.

매출 환급 출금은 기준일에 도래한 잔액을 **송금 준비표**에 표시한다. 거래처의 검증된 은행·계좌·예금주 및 현장/본사 구분이 필요하다. 매입 환급 입금은 입출금 예정·실적과 자금 전망에서 확인한다. 출력/검토본은 실제 이체를 실행하지 않는다.

## 입력 오류 정정

환급 실적이 있으면 최근 연결부터 해제한다. 그 후 수정증빙 상세의 **입력 오류 정정 · 원본 청구 복원**을 사용한다. 환급 계획은 종료하고 취소/정정·해제 이력을 보관한다. 원래 지급 기록과 실제 은행 거래는 보존한다. 일부 지급 원본의 입력 오류 정정은 원래 예산안의 미지급 잔액도 복원한다. 마감월과 원 지급 기준의 변경을 검사한다.

환급 전용 계획은 다른 청구·급여·정기지급·어음·차량 비용의 일반 일정으로 승계하거나 통합할 수 없다. 계획의 금액·현장·내용을 일반 일정 정정으로 바꿀 수 없다. 원 지급 연결도 취소 등록이 유효한 동안 해제할 수 없다. 환급 통장 거래와 청구 은행 연결의 이중 사용을 양쪽에서 차단한다.

## 회계 전달과 기간

수정증빙은 원본 취소에 반영하며 음수 공급가액·세액을 다시 합산하지 않는다. **기지급 취소 환급 정산** 참고표에 원 지급 보존액, 예정액, 해당 전달월 말까지의 환급액, 잔액, 해당 전달월 환급액, 은행 연결/해제 이력을 담는다. 다음 달에 환급하거나 미환급 상태로 남아 있어도 원본 수정 XLSX를 회계 전달 ZIP에 포함한다. 일부 지급 취소가 있으면 원 청구액과 미지급 취소액도 구분한다. 실제 통장 자료와 이 표를 비용·세액으로 중복 합산하지 않는다. 이후 달의 환급을 앞선 달 전달본에 소급해서 더하지 않는다.

## 이번 구현의 범위

- 같은 달 작성의 **은행 지급액이 대조된 원본**을 전액 취소하고, 환급 은행 실적은 이후 달에도 연결한다.
- 일부 지급 원본도 지원하며 원 지급액보다 큰 환급 예정은 만들지 않는다. 부분 환급만 받기로 합의한 감액/면제와 다른 달 작성 수정증빙은 자동 처리하지 않는다.
- 부분 감액·자재·차량·공사 원가 배부·정기지급 연결이 있는 원본은 별도 정산 대상으로 보류한다.
- 환급 연결 취소증빙을 재발급 승계 원본으로 사용할 수 없다. 재발급과 환급의 상계/승계는 후속 개발 범위다.
- 회사 PC/NAS 설치·실자료 이관·회계사무소 판단 검증은 별도로 남아 있다.

# 회사 PC 시범운영 안내

현재 운영 방향은 **회사 메인 PC에서 ERP와 PostgreSQL 실행, NAS에 백업 보관**이다. 별도 서버 구매나 유료 클라우드 가입은 시범운영의 전제가 아니다. 클라우드 개발 환경은 회사 업무 서버와 별개이며, 회사 PC 설치·실제 원본 대조는 아직 완료하지 않았다.

## 시범운영을 시작하는 조건

1. 메인 PC의 Windows 10 64비트·CPU·여유 저장공간과 RAM 8GB, 인터넷 팩스 동시 사용 상태를 확인한다. 개발 환경의 검사 통과가 회사 PC 구동 보장은 아니다.
2. Node.js 24와 PostgreSQL 17, ERP 전용 DB·계정을 준비한다. 기존 팩스·다른 프로그램의 DB를 재사용하지 않는다.
3. `.env.office.example`을 참고해 회사 PC 안에서 `.env.office`를 설정한다. 실제 비밀번호와 세션 키는 Git이나 채팅에 보내지 않는다.
4. 먼저 `ERP_OFFICE_BIND=127.0.0.1`로 시험한다. `ERP-install.cmd`가 성공하면 `ERP-start.cmd`로 실행하고 메인 PC 브라우저에서 로그인한다.
5. 별도 시험 DB와 가상자료로 저장·재조회·엑셀·인쇄·JPG·백업/복구를 확인한다. 그다음 원본 사본을 이용해 작은 범위의 실제 자료를 대조한다.

설치와 위 확인이 정상 완료된 뒤 1~2영업일의 소량 자료 대조를 거쳐 기존 엑셀과 병행하는 시험을 목표로 한다. 회사 장비/자료에서 발견되는 문제에 따라 조정한다. 설치 완료나 사용 가능 날짜가 확정된 상태는 아니다.

자세한 설치 순서: [회사 PC + NAS 운영 준비](OFFICE-PC-AND-NAS.md).

## 첫 시험 자료와 비교 항목

- 별도 시험 DB에서 공사 1건, 통장 1개와 소량 입출금, 매입/매출 각 1건을 확인한다. 선택한 계좌의 원본 금액·잔액과 비교한다.
- 회사 실제 계좌는 하나 2, 기업 1, 전북 1, 국민 1, 우리 2, 신한 1의 총 8개다. 회사 전체 자금 판단 전 모든 실제 계좌를 등록·대조한다. 한 계좌 시험 잔액을 회사 전체 잔액으로 쓰지 않는다.
- 확인된 마이너스 약정은 전북 200,000,000원(2026-11-02 재확인), 신한 50,000,000원이다. 한도는 실제 사용액·은행 잔액과 별개이며 현금에 더하지 않는다.
- 급여는 한 달·한 명부터 근로계약/공수/공제/실지급액을 원본과 비교한다. 상용직·일용직 명세서, JPG 파일명과 A4 한 쪽 인쇄를 확인한다.
- 자재는 직납/창고 입고·이동·사용을 소량 확인한다. 품목 금액과 원가 배부, 미사용 재고의 처리 기준은 회계사무소와 별도 대조한다.

## 송금 준비와 지급 확인

다음 달 말일 지급 거래처를 등록하고 9월 청구가 10월 31일인지 확인한다. 월세·전기요금은 지급월을 준비하고 기존 청구/예정과 중복하지 않게 연결한다.

송금표의 수취계좌·예금주·공사·금액을 원본과 대조한 뒤 선택 내역만 인쇄한다. 이미 지급한 건은 은행 연결 후 남은 잔액만 표시되어야 한다. 여러 공사로 배부한 계산서는 공사 필터에서도 전체 청구 미지급액을 한 번 표시한다. 출력·구두승인 기록이 은행 송금을 실행하지 않는다.

사용법: [송금 준비](TRANSFER-PREPARATION.md), [인사·급여](LABOR-AND-PAYROLL.md), [차량·고지서 지급](VEHICLE-PAYMENT-WORKFLOW.md), [매입 공사 배부](PURCHASE-ALLOCATION.md).

## 백업과 복구 확인

사용자가 확인한 자료 경로는 `\\192.168.0.250\work\동양계전ERP`이며 통장 입출금과 급여대장이 보관돼 있다. 원본 자료는 보존하고, 백업은 별도 하위 폴더 `04_ERP백업`에 보관할 계획이다. 회사 PC의 실행 계정으로 접근·쓰기 권한과 검증 복사를 시험하기 전에는 NAS 연결 완료로 간주하지 않는다. 회사 PC 단독 시험과 로컬 백업부터 진행할 수도 있다. NAS에 실시간 DB 파일을 직접 두지 않는다.

- 로컬 백업: `npm run office:backup`
- 별도 빈 DB 복구: `.env.office`의 `ERP_RESTORE_DATABASE_URL`을 별도 복구 DB로 설정한 뒤 `npm run office:restore -- "백업파일.dump"`

복구는 원본 업무 DB나 자료가 있는 DB에 덮어쓰지 않는다. 백업에는 첨부·급여 등 회사 자료가 포함되므로 회사의 비공개 보관 경로를 사용한다. 기존 NAS 자료를 자동 이관하거나 삭제하지 않는다. 실제 예약 백업과 정전/재시작 후 확인은 회사 장비에서 시험해야 한다.

## 업무 전환 기준

저장 후 재조회·원본 금액 대조·출력·첨부 다운로드·별도 DB 복구까지 통과한 범위부터 기존 엑셀과 병행한다. 실제 은행 송금·급여 신고·세무 신고는 원본과 담당자의 최종 확인을 거친다. 개발 검사 통과만으로 기존 장부 전체를 대체하거나 세무 신고를 자동 확정하지 않는다.

## 시범 운영에 집중할 범위

상세 시작 기준은 [시범 운영 시작](PILOT-START.md)에 모았다. 프로그램 전체 완성과 회사 장비 설치 완료를 같은 상태로 취급하지 않는다. 먼저 통장 하나·공사 하나·급여 한 달의 병행 대조를 진행하고, 원본 엑셀을 계속 유지한다. 설치 전 `ERP-check.cmd`로 필요한 구성부터 확인한다. 현재 회사 PostgreSQL 설치·ERP 실행·실제 백업 복원은 아직 완료하지 않았다.

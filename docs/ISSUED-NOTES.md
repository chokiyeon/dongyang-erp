# 발행어음대장

자금 관리 → 발행어음대장 (`/issued-notes`). 이미 회사에서 발행한 어음을 기록하며, 은행에 어음을 발행하거나 이체를 실행하는 기능은 아니다.

## 등록과 만기

수취 거래처, 관련 현장, 지정 결제 계좌, 실제 발행일, 어음금액, 등록 사유를 입력한다. 어음번호/관리번호는 회사 내에서 유일하다.

발행일의 같은 날짜에서 달력상 3개월 뒤를 만기로 계산한다. 대상 월에 같은 날짜가 없으면 해당 월 말일을 쓴다. 예: 1월 31일 → 4월 30일, 7월 31일 → 10월 31일. 윤년과 연도 변경을 반영한다. 휴일에 따른 은행 결제일 조정은 하지 않는다.

잘못 등록한 경우 등록 취소 후 다른 관리번호로 다시 기록하고 원래 번호를 비고에 남긴다. 현재 등록 후 금액·발행일을 직접 수정하는 기능은 제공하지 않는다.

## 자금계획 중복 방지

등록할 때 반드시 다음 중 하나를 선택한다.

- 기존 예정 연결: 회사의 미처리 ‘어음결제’ 지출 예정 중 금액·만기일이 같고 다른 어음에 연결되지 않은 내역만 연결한다. 처리 실적이 있으면 연결하지 않는다. 연결 시 확정 예정으로 바꾼다.
- 신규 만기 예정: 같은 어음 지출 예정이 없다는 확인을 받고 확정 지출 예정을 생성한다.

어음 하나에 예정 하나만 연결한다. 기존 예정을 연결하면 새로운 예정은 만들지 않는다. 별도 등록한 제목만 다른 중복 일정을 의미로 자동 판별하지는 못하므로 신규 생성 전 기존 예산안을 확인해야 한다.

목록은 상태·거래처·어음번호·만기 기간으로 검색하며 50건씩 표시한다. 조회 합계는 조건 전체 기준, 월별 만기 표는 필터와 별도로 회사 전체 미결제 어음을 합산한다. 이 표를 자금계획에 다시 더하지 않는다.

## 실제 결제와 복원

어음 상세 → ‘은행 출금으로 어음 전액 결제 반영’에서 연결된 예정의 처리 화면을 연다.

- 지정 결제 계좌의 실제 은행 출금에 어음금액 전액을 연결해야 한다. 수기 처리·일부 금액·차액 정산으로 어음을 완료할 수 없다.
- 실제 처리일은 은행 거래일을 사용하고 발행일 이전 거래는 사용할 수 없다. 만기 전 실제 상환은 기록할 수 있다.
- 기존 은행 거래의 다른 예정 실적을 포함해 출금액을 넘는 연결을 차단한다. 은행 거래를 새로 만들거나 금액·잔액을 변경하지 않는다.
- 처리 완료 시 어음도 ‘결제 완료’로 바뀌고 남은 예정은 0원이 된다. 자금 전망은 만기 지출을 다시 빼지 않고 기준 잔액일 이후 실제 처리액을 반영한다.
- 잘못 연결한 최근 실적을 취소하면 어음은 ‘미결제’, 완료일은 빈값으로 복원되고 남은 만기 예정도 돌아온다. 실제 이체 취소·환불을 뜻하지 않는다.

## 등록 취소와 이력

미결제이고 유효 처리 실적이 없는 어음만 등록 취소할 수 있다. 취소 시 연결된 만기 예정도 실제 처리액 없이 종료해 전망에서 제외한다. 결제 완료 어음은 먼저 잘못된 결제 실적을 취소해야 한다. 원본 등록과 취소·결제·복원 이력, 사유는 보관한다.

회사 소유권, 어음 버전과 예정 버전, 은행 연결 버전, 요청 재전송을 검증하며 DB 트랜잭션으로 함께 처리한다.

## 범위

이번 범위는 회사가 발행한 어음이다. 수취어음 보유·추심·할인·만기 확인은 별도 RECEIVED-NOTES.md를 참고한다. 배서·부도와 매입채무의 지급어음 대체 분개는 후속 기능이다. 어음 등록만으로 매입 미지급금이나 공사 원가를 차감하지 않는다. 같은 실제 은행 출금을 매입 정산과 예정 실적에 각각 연결할 수 있지만 다른 관점이므로 합산해 현금 지출로 다시 세지 않는다.

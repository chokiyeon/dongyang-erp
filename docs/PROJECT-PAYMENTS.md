# 현장별 지급 현황

메뉴: 공사 관리 → 현장별 지급 현황 (`/project-costs`). 통합 장부의 출금 행에서도 ‘현장 배분’으로 이동한다.

## 처리 흐름

1. 등록된 은행 출금 거래를 선택한다.
2. ‘배분 행 추가’로 현장·자재비/인건비/기타비·금액을 기록한다. 한 출금을 최대 20개 항목으로 나눌 수 있다.
3. 본사·공통·공사 외 지급은 현장을 지정하지 않는다.
4. 출금액·배분 합계·미배분 금액과 사유를 확인하고 저장한다. 일부만 배분할 수 있다.
5. 변경 시 기존 배분을 불러와 수정한다. 모든 행을 삭제하고 사유와 함께 저장하면 배분을 해제한다.

예: 300만 원 출금을 A현장 자재비 100만 원, B현장 인건비 150만 원으로 기록하면 50만 원은 미배분으로 남는다. 기존 미확인 금액을 임의로 현장 원가로 확정하지 않는다.

## 집계 기준

- 현장별 합계는 조회 지급기간 전체에 대해 자재비·인건비·기타비를 합산한다. 날짜를 비우면 전체 기간이다.
- 별도 출금 내용 검색은 하단 목록에만 적용된다. 하단 목록과 엑셀 저장은 현재 페이지 50건 기준이다.
- 회사 계좌 간 이체는 제외한다. 내부이체를 현장 지급으로 배분할 수 없다.
- 실제 출금액 기준이다. 부가세 포함 여부, 급여 공제, 미지급 매입·급여를 보정한 세무 원가나 손익이 아니다. 계약 공급가액과 차감해 이익을 표시하지 않는다.
- 본사·공통·공사 외에는 현장 외 지급을 보관하며 이 항목 전체가 비용이라는 의미는 아니다.
- 어음 발행 시점의 매입·현장 원가 및 급여 작업일보에서 자동 배분하는 기능은 후속 범위다. 이 화면은 은행 출금의 수동 배분이다.

## 저장 및 변경 보호

- 회사 거래·회사 현장만 허용하며, 신규 배분은 사용 중인 현장으로 제한한다. 기존에 연결된 사용 중지 현장은 수정 시 유지할 수 있다.
- 양수 정수 금액, 출금액 이하 합계, 분류와 현장 조합을 서버에서 검증한다. 금액은 정수 문자열과 Decimal/BigInt로 처리한다.
- 별도 배분 버전으로 동시 수정을 확인하고 한 DB 트랜잭션에서 전체 교체한다. 동일 요청 재전송은 중복 이력을 만들지 않는다.
- 적용 전후 배분과 사유를 이력으로 저장한다. 은행 거래일·금액·잔액·계정과목은 변경하지 않는다.
- 현장 배분이 있는 거래를 내부이체로 바꾸려면 먼저 배분을 해제해야 한다. 묶음 분류 되돌리기에도 같은 규칙을 적용한다.

## 검증

DB 검증: 두 현장 분할, 본사 지급, 일부 미배분, 금액·20자리 잔액 보존, 초과 금액 및 다른 현장 거절, 재요청, 버전 충돌, 사용 중지 현장 유지, 내부이체 전환 차단, 배분 해제, 묶음 되돌리기 보호.

브라우저 검증: 합성 300원 출금 → 두 현장에 100원·150원 배분 → 미배분 50원 및 현장별 합계 확인 → 저장 후 배분 해제 → 미배분 300원 확인. 실사용 장부는 가져오거나 배분하지 않았다.

# 자재 전량 반품 후 정식 전액취소

원 입고 수량을 공급처에 모두 실제 반환한 매입 청구를, 음수 전액취소 계산서와 대조한다. 미정산·일부/전액 지급 원본과 같은 달/다른 달을 구분한다. 자재·은행 원본을 삭제하거나 수량을 허위로 조정하지 않는다.

## 사용

1. 자재·재고에서 원 입고의 실제 공급처 반품을 기록한다. 단가 감액만으로 수량이 남은 경우를 전량 반품으로 취급하지 않는다.
2. 매입매출 원본 엑셀 검토에서 해당 전액취소 검토를 선택한다.
3. 원본 청구와 대조할 미사용 반품을 선택한다. 선택한 조정 공급가액은 이번 취소 공급가액과 같아야 하고, 원 입고별 실제 반품 수량이 모두 일치해야 한다. 연결 품목 공급가액 순액도 0이어야 한다.
4. 기지급 원본은 별도 환급 예정일을 입력하고 실제 은행 입금과 대조한다. 미지급 잔액은 종료하고 실제 지급액만 환급한다. 기존 부분 감액 환급액은 이번 환급에 다시 넣지 않는다.

기존 부분 감액에 대조한 반품은 전액취소에 재사용하지 못한다. 이후 반환한 나머지 자재만 잔액 취소와 대조한다. 예를 들어 110만 원 전액 지급 후 22만 원 부분 반품 감액과 88만 원 잔액 취소를 하면 환급 예정은 각각 22만 원·88만 원이다. 같은 은행의 합산 110만 원 입금에 나눠 연결할 수 있지만 총 연결액이 은행 입금액을 넘지 못한다.

## 원본·정정·기간

원 입고·실제 반품·원 지급을 보존한다. 취소에 사용한 반품의 원 입고 연결이나 조정 자체를 임의 변경/취소하지 못한다. 잘못 연결한 취소 등록은 환급 은행 실적을 먼저 확인한 뒤 정정한다. 이때 실제 반환한 수량을 창고에 다시 넣지 않으며 반품은 미대조 상태로 유지한다.

지급 예산안이 있는 기지급 원본은 당초 계획액과 실제 지급 이력을 유지하고 미지급 잔액만 종료한다. 입력 정정 시 그 미지급 잔액을 복원한다. 실제 환급은 별도 예정·실적이며 가상 은행 거래를 만들지 않는다.

다른 달 취소는 원 작성월 금액과 당시 은행 원본을 유지하고 수정 작성월에 음수 금액을 한 번 반영한다. 대조 확인일의 전후 관계를 기록해 과거 반품 월의 전달본도 보존한다. 원본 월을 단지 대조 연결 때문에 다시 열지 않는다. 취소 작성월·실제 환급 월·현재 대조 확인월의 마감 보호는 유지한다.

원본/수정계산서, 반품과 전액취소의 연결 및 연결 변경 이력을 회계 전달본과 원본 묶음에 포함한다. 이 참고표의 금액을 원가·세액에 재가산하지 않는다. 차량·공사 배부 연결을 이 경로로 우회하지 않는다.

## 검증과 범위

StockMovement의 전액취소 관계를 추가한 52번째 nullable 마이그레이션을 적용했다. 기존 부분 감액의 요청 지문은 그대로 유지해 재시도 호환성을 보존한다. 일반 문서 취소에 화면 입력으로 자재 검사를 우회하는 옵션을 제공하지 않는다.

전체 단위/DB 176개(`/tmp/stock-cancel-full1.log`), 집중 26개(`/tmp/stock-cancel-focused2.log`), 전량 반품/부분 반품·가격 감액/은행 환급 화면 6개(`/tmp/stock-cancel-browser1.log`), 타입(`/tmp/stock-cancel-types3.log`), lint(`/tmp/stock-cancel-lint1.log`)와 운영 빌드(`/tmp/stock-cancel-build2.log`) 통과. 52개 마이그레이션 체크섬·원본 바이트·20자리 금액의 격리 DB 백업/복구와 덮어쓰기 차단도 통과(`/tmp/stock-cancel-backup.log`). 실제 회사 자료 자동 이관·실제 송금·회사 PC/NAS 설치는 미실행이다.

수량이 남은 가격 감액 원본의 단순 전액취소, 미정산 원본의 기존 예산안 후속 정산, 차량/공사 배부 연결 정산과 실제 비은행 상계는 별도 잔여 범위다.

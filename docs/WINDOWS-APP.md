# 윈도우 ERP 실행기

설치·DB 준비·빌드를 완료한 메인 PC에서 ERP-App-install.cmd를 한 번 실행하면 현재 사용자의 바탕화면에 동양계전 ERP와 ERP 서버 종료 바로가기를 만든다. 관리자 설치나 별도 서버 구매는 필요 없다. 폴더를 옮기면 바로가기를 새 폴더에서 다시 준비한다. 다른 폴더를 가리키는 기존 ERP 바로가기는 자동 덮어쓰지 않는다.

동양계전 ERP 아이콘을 누르면 회사 설정을 확인하고 서버를 준비한 뒤 독립된 Edge/Chrome 앱 창으로 연다. 기존 ERP가 준비돼 있으면 서버를 중복 실행하지 않는다. 브라우저를 찾지 못하면 기본 브라우저로 연다. 설치 파일이나 빌드가 없거나 다른 프로그램이 같은 포트를 사용하면 설명을 표시하며 해당 프로그램을 종료하지 않는다. 암호는 실행 인자나 안내 창에 넣지 않는다. 실행 로그는 ERP 폴더의 logs에 보관한다.

앱 창을 닫아도 메인 PC의 ERP 서버는 계속 실행되므로 경리 PC에서 계속 접속할 수 있다. 서버를 종료해야 하면 ERP 서버 종료를 사용한다. 이 실행기가 만든 서버의 PID·실행 경로·명령·포트를 확인하고 사용자가 확인한 경우만 종료한다. 수동 명령창에서 켠 서버는 해당 창에서 중지한다. PostgreSQL·다른 Node 프로그램·회사 자료를 삭제하거나 일괄 종료하지 않는다.

사내 연결은 .env.office의 ERP_OFFICE_BIND를 메인 PC의 실제 사내 IPv4로 지정하고 재시작한다. 현재 사용자 확인 메인 PC 주소는 192.168.0.12이므로 경리 PC에서는 http://192.168.0.12:3000을 사용한다. 메인 PC가 켜져 있고 두 PC가 같은 사내망에 있어야 한다. 방화벽은 필요할 경우 해당 PC·포트·사내 서브넷·Private/Domain 프로필 범위만 허용한다. 일반 실행기는 방화벽이나 공유기를 변경하지 않는다. 사내 접속을 설정하려면 별도의 ERP-LAN-setup.cmd를 실행한다. 관리자 권한 승인을 받은 뒤 실제 이 PC에 연결된 사내 IPv4와 포트를 확인하고 Node 프로세스·해당 주소/포트·LocalSubnet·Private/Domain에 한정된 방화벽 규칙을 만든다. 공용 프로필은 허용하지 않고 다른 규칙은 덮어쓰지 않는다. 실행 중인 서버가 있으면 먼저 종료하도록 안내한다. 인터넷 포트 개방은 필요 없다. NAS 주소와 메인 PC 주소는 서로 다르다.

이 기능은 현재 웹 ERP를 윈도우 아이콘과 브라우저 앱 창으로 연결하는 실행기다. ERP·Node.js·PostgreSQL을 모두 포함한 독립 EXE 설치 패키지가 아니다. 매일 cmd/npm을 입력하지 않고 사용하기 위한 방식이다. 윈도우 실제 GUI·바로가기·백그라운드 종료와 사내 방화벽은 회사 PC에서 확인해야 한다.

업데이트 시 기존 ERP 실행을 중지하고 검증된 배포본의 소스 파일을 기존 프로그램 폴더에 덮어쓴다. .env.office·ERP-login.txt·기존 DB·NAS 원본·backups는 보존한다. 새 소스만 들어 있는 배포본에는 이 개인 설정 파일이 없다. 회사 정보 필드 추가는 새 마이그레이션이므로 ERP-install.cmd 또는 npm ci → npm run office:prepare → npm run build:office를 거쳐야 한다.

경리 PC에는 Node.js나 PostgreSQL을 별도로 설치하지 않는다. 배포본의 client 폴더만 경리 PC에서 열고 ERP-Client-install.cmd를 실행해 메인 PC 주소 192.168.0.12를 입력하면 경리 PC 바탕화면에 연결 아이콘을 만든다. 비밀번호·DB 접속 설정을 client 폴더로 복사하지 않는다. 연결 아이콘은 Edge/Chrome 앱 창으로 메인 PC에 접속하며 메인 PC 서버를 원격으로 켜지 않는다. 메인 PC가 꺼져 있으면 업무할 수 없다.

# 현재 구현 상태

## 사용할 수 있는 개발 기능

- 관리자 로그인·로그아웃: 8시간 유효한 서명 쿠키, 비밀번호 변경 시 세션 무효화
- 회사 등록·수정, 복수 대표자 입력
- 거래처 등록·수정·검색, 발주처/매입처/겸용 구분, 사용 중지
- 현장 등록·수정·검색: 발주처, 공종 복수 선택, 담당자, 주소, 기간, 상태, 계약 공급가액
- 계좌 등록·수정·검색: 6개 은행, 업무 별칭, 마이너스 한도 미확인(null)과 0원 구분
- 입출금 예정 수기 등록: 방향, 확정/예상, 항목, 예정일, 원래 금액 보존
- 실제 처리액 추가: 일부 처리, 전액 완료, 차액 정산 완료, 사유·실제 처리 이력 보관
- 처리 버전과 요청 식별자로 동시 수정·같은 처리 재요청의 이중 반영 방지
- 기준일 종료 순잔액 수기 설정과 변경 이력
- 3/6개월 날짜별 자금 전망, 월말 잔액, 확정입금 기준 첫 부족일

현재 관리자 한 명을 위한 개발용 접근제어다. 직원별 계정·역할·감사로그·다중 인스턴스 로그인 제한은 별도 구현이 필요하다.
비밀번호는 환경변수로 주입하고 브라우저나 Git에 공개하지 않는다.
다른 사용자의 프로젝트에 접근하는 다중 법인 시스템은 아니다.

## 자금 전망의 해석

- 8개 계좌의 실제 잔액을 합산한 순잔액을 기준으로 한다. 미사용 대출 한도는 더하지 않는다.
- 기준일 종료까지 이미 반영된 실제 거래는 계산에서 제외한다.
- 기준일 이후 실제 거래와 아직 남은 예정액만 계산한다.
- 완료된 예정은 실제 처리액만 남기고 나머지 차액을 향후 예정에서 제외한다.
- 확정입금 기준 전망도 예상 지출은 포함한다. 예상입금 포함 전망과 함께 표시한다.
- 기준일 이전에 남아 있는 미처리 예정은 기준일 다음 날 처리된다고 가정하고 건수를 알린다.
- 날짜별 순잔액이므로 당일 출금이 먼저 발생하는 상황을 검증하는 기능은 아니다.
- 기준일 다음 날이 속한 달부터 3개/6개 달의 말일까지 계산한다.
- 기준 잔액이 없으면 0원을 가정하지 않고 계산을 보류한다.

이 계산은 등록된 수기 자료 범위의 전망이다. 실제 은행 잔액 대조나 미등록 부채의 완전성을 보장하지 않는다.
매입·매출 미수·미지급과 자금 예정은 별도 자료이며, 연결하지 않은 자료를 자금 전망에 자동 추가하지 않는다. 정산 완료는 법적 채무 감액을 의미하지 않는다.

## 남은 개발 범위

- 은행별 실제 양식 추가 매핑, 내부이체 쌍 연결, 계약 변경·공사 수금 일정
- 매입 명세서 전체 자동 대조·품목 배분과 재고 평가 방법 검토
- 노무 신고·공제·회사 부담분 자동 산정의 실제 기준 검토
- 차량 증빙·은행 연결·정비 주행거리, 실제 세무 기준·전달 형식 대조
- 운영용 개인 계정·권한·공개 배포·예약 백업·첨부 저장소

개발 완료와 운영 개통은 별도입니다. 현재 기능의 세부 기준은 아래 항목별 문서를 따릅니다. 목표 전체 기능을 완료한 상태는 아닙니다.

## 검증

- `npm test`: 정밀 금액·실제 날짜, 기준정보·범위·중복·버전 충돌, 일부/완료 지급, 재요청, 자금 전망·기준 잔액 검증
- `npm run test:e2e`: 시스템 Chromium에서 로그인, 회사·거래처·현장·계좌, 부분 지급·정산, 자금 전망, 로그아웃 검증
- 테스트는 실제 거래 원본을 사용하지 않는다. DB 테스트는 롤백하고 브라우저 테스트는 고유 코드의 생성 자료만 정리한다.

## ERP 화면과 출력 도구

- 상단 업무 분류, 좌측 세부 메뉴, 현재 화면 탭·경로, 압축된 조회 조건과 장부형 표로 구성한다.
- 업무 현황의 금액은 등록된 기준 잔액·미처리 예정에서 집계한다. 실시간 은행 잔액으로 표시하지 않는다.
- 저장: 현재 입력 중인 양식을 제출한다. 포커스가 없으면 첫 양식을 사용한다. 입력 양식이 없는 종합 현황에서는 비활성화한다.
- 미리보기: 현재 조회된 표와 입력 양식을 보고서로 보여준다. 입력값은 저장 여부 별도 확인 문구로 구분한다.
- 프린트: 보고서 전용 인쇄 레이아웃으로 사용자의 브라우저 인쇄 창을 호출한다. 실제 프린터 선택·인쇄 여부는 사용자가 결정한다.
- 엑셀로 저장: 조회 범위와 입력값을 실제 .xlsx 파일의 시트로 내보낸다. 화면에서 제공하는 최대 200건 제한을 그대로 따른다.
- 인쇄·엑셀에서는 수정·처리 버튼 열을 제외하고 금액 열을 구분한다. Excel의 15자리 정밀도를 넘는 금액은 문자열로 보존한다.
- 모바일에서는 업무 메뉴를 접고 표 안에서 가로 스크롤한다.

## 통합 은행 장부

- `/ledger`: 6개 은행·등록 계좌 전체의 실제 거래 통합 조회, 날짜·은행·계좌·입출금·적요 필터
- 입력 계좌는 사용 중인 자사 계좌인지 서버에서 검사한다. 사용 중지된 계좌의 과거 내역 조회는 유지한다.
- 조회 전체 입금·출금·순입출금과 계좌별 합계, 페이지당 50건 목록
- 직접 등록, .xlsx 미리보기·계좌 지정 후 가져오기, 공통 양식 다운로드
- 5MB·1,000건 제한, 첫 시트의 앞 30행에서 공통 열 이름 탐색
- 같은 파일 해시·계좌·행은 건너뛴다. 겹치는 다른 파일의 날짜·방향·금액·적요가 같은 거래는 확인을 요구하고 확인 후 추가할 수 있다.
- 서로 다른 실제 거래가 동일 날짜·금액·적요일 수 있으므로 의심만으로 자동 삭제하지 않는다.
- 실제 거래 금액과 은행 제공 잔액을 구분하며 불명 잔액은 미등록으로 둔다.
- 회사 내부 이체는 태그로 표시한다. 자동 쌍 연결·분류 및 복식회계 분개는 아직 구현하지 않았다.
- 은행 거래와 CashSettlement는 별도 자료이며 자동 합산·자금 전망 연동을 수행하지 않는다.
- 실제 은행별 파일 샘플은 미확인이다. 모든 은행의 모든 다운로드 변형을 검증한 것은 아니다.
- 장부 확정 거래의 정정·취소 UI는 후속 구현이다.

## 회계코드와 거래 목적 분류 (2026-10-31)

[새 계정과목 표](ACCOUNTING-CHART.md)는 건설업 세무회계 계정과목을 기준으로 정리한 67개 계정이다. 번호는 이 ERP의 내부 관리 번호로 특정 회계 프로그램이나 법정 공통 번호가 아니다.
사용자 요청에 따라 기존 코드 체계를 전환했다. 코드 정의·거래 연결·계좌 코드의 이전 상태는 AccountingCodeTransition에 보관하고 기존 거래의 일자·금액·잔액은 유지한다. 불명확한 기존 분류는 미분류로 남긴다.
전환은 1회 DB 마이그레이션이며 재시작·반복 배포 때 사용자 수정값을 덮어쓰지 않는다. 기존 BankAccount.accountingCode 열은 이전 데이터 호환용으로 남기되 입력·상속·표시에는 사용하지 않는다.

- 계좌 관리의 고정 회계코드 입력을 제거하고 장부 거래별 계정만 사용한다.
- '무엇을 지급·수금했나요?'에서 쉬운 업무 이름을 고르면 연결 계정명·번호·주의사항을 표시한다.
- 전기·수도·가스, 과태료, 정수기·복합기 렌탈, 현장 장비 임차, 차량 일반 렌트 등을 분리한다.
- 입금·출금에 맞지 않는 업무 선택을 UI와 서버에서 거부한다. 전문가의 직접 계정 선택은 별도 메뉴다.
- 대출 원금+이자, 4대보험 합산, 계약 미확인 렌탈은 미분류로 저장할 수 있으며 한 코드로 임의 확정하지 않는다.
- 적요 키워드만으로 코드를 확정하지 않는다. 입력 시 사용자가 업무 종류를 선택하고 안내를 확인한다.
- 장부 '계정 수정'에서 금액을 바꾸지 않고 분류를 수정하고 사유·이전/새 코드 이력을 보관한다. 버전 충돌을 검사한다.
- 사용자가 추가 계정 등록·수정·엑셀 가져오기를 할 수 있다. 표준 연결 코드가 중지·변경되면 해당 업무 선택을 비활성화한다.
- 은행 엑셀의 신규 거래는 미분류로 들어온다. 자동 분개·세금 신고·대량 자동 재분류는 구현하지 않았다.

기존 장부 분석과 복잡한 거래의 분류 원칙은 [장부 검토](EXISTING-LEDGER-REVIEW.md)를 참고한다.

## 기존 연도별 장부 가져오기

`자금 관리 → 기존 장부 가져오기`에서 사용자가 올린 장부의 시트를 선택해 검토한다.
확인된 형식은 A 날짜, B 이전 구분, C 은행, D·E 거래내용, F 차입 입금, G 일반 입금, H 출금, I 원장 누계다.
D·E 내용은 함께 보존하며 같은 내용은 중복하지 않는다. 병합 셀은 파일이 제공하는 값을 읽되 실제 빈 날짜는 앞 행에서 임의로 채우지 않는다.

- 이월·기초 잔액·합계·금액 없는 행은 실제 입출금으로 가져오지 않는다.
- 날짜 누락·불가능/미래 날짜·음수·두 입금 열 동시 금액·입출금 동시 금액·현금·불명확 은행은 별도 확인 목록으로 분리한다.
- 파일 5MB 이하, 선택 시트 10,000행 이하. 원장 은행 표기마다 실제 자사 계좌를 명시적으로 연결하며 행별 계좌 변경도 가능하다.
- 후보를 250건씩 표시하고 가져올 행을 사용자가 선택한다. 선택 행의 계좌가 모두 지정돼야 가져올 수 있다. 서버도 자사·사용 중 계좌·은행 일치를 검사한다.
- 동일 원본 파일·시트·원본 행은 계좌 선택을 바꿔도 새 거래로 복제하지 않는다. 이미 다른 계좌·내용으로 가져온 행이면 확인을 요구한다.
- 다른 파일의 같은 날짜·금액·적요는 중복 의심 확인을 거친다.
- 이전 구분은 `legacyCategory` 참고 정보이고 새 `accountingCodeId`·`businessType`은 미분류로 저장한다.
- 원장 누계 `legacyLedgerBalance`는 보관하되 은행의 `bankBalance`로 적용하지 않는다. 예산이나 통장 잔액으로 자동 반영하지 않는다.
- 출처 시트·행·은행 표기·차입/일반 입금 구분을 보관한다. 재가져오기는 사용자가 나중에 수정한 회계 분류를 덮어쓰지 않는다.
- 원본 엑셀은 수정하지 않는다. 실제 사용자 장부 전체를 자동 이관한 것은 아니며 계좌 확인·선택 전까지 DB에 반영하지 않는다.
- 가져오기 화면의 인쇄·엑셀 보고서도 드롭다운의 전체 후보가 아니라 실제 선택된 계좌만 출력한다.

계좌 연결 오류 정정·가져온 배치 일괄 취소 UI는 후속 범위이므로 가져오기 전에 원장과 실제 계좌를 대조해야 한다.

### 미분류 묶음 정리
- `/ledger/classify`: 입금·출금을 나눠 거래 내용과 이전 분류로 검색하고 최대 100건씩 선택한다.
- 용도 선택에 따른 계정 안내, 선택 합계, 사유와 명시적 확인을 거쳐 적용한다. 이전 분류/적요만으로 자동 확정하지 않는다.
- 분류 버전과 회사 소유권을 검증하고 한 DB 트랜잭션에서 적용한다. 요청 식별자 재사용은 중복 적용하지 않는다.
- 작업별 적용 전후 분류, 내부이체 여부, 적용 버전을 저장한다. 최근 작업에서 되돌리기를 검토할 수 있다.
- 적용 후 개별 수정된 거래가 있으면 전체 되돌리기를 거절한다. 거래일·금액·은행 잔액은 변경하지 않는다.
- 실제 사용자 장부는 임의로 분류하지 않았다. 회사 계좌 연결 후 가져온 거래에 사용한다.

### 현장별 은행 지급 배분
- `/project-costs` 및 통합 장부의 ‘현장 배분’ 연결 구현. 지급기간 현장별 합계, 배분/미배분 합계, 출금 검색 및 50건 페이지 조회.
- 출금 1건을 최대 20개 현장·구분으로 분할. 본사·공통·공사 외 구분 포함. 전체 배분 해제와 변경 이력 저장.
- 배분 버전, 사유, 요청 중복 보호. 내부이체와 현장 배분의 충돌 방지(개별/묶음 분류 및 묶음 되돌리기 포함).
- 실제 출금 기준의 관리용 지급액이며 세무 원가·손익으로 표시하지 않음. 상세: PROJECT-PAYMENTS.md.

### 현장별 지급예산
- `/project-budgets`: 자재비·인건비·기타비의 전체 공사기간 지급예산과 현장 배분 누적 출금 비교.
- 미등록/0원 구분, 일부 미등록 시 전체 차액 보류, 항목별 초과 및 지급률 표시.
- 별도 예산 버전·사유·요청 중복 보호 및 변경 전후 감사 이력. 계약금액·은행 거래·현장 배분에는 영향 없음.
- 회사 자금계획과 구분하며 미지급 채무·이익으로 표시하지 않음. 상세: PROJECT-BUDGETS.md.

### 청구·증빙, 미수·미지급, 부가세와 자금계획 은행 연결
- `/trades`: 매입·매출 등록/수정/취소, 거래처·현장·금액·증빙 검토 및 변경 전후 이력, 50건 페이지 조회.
- 기존 은행 거래의 분할 정산·여러 문서 연결·해제. 문서와 은행 버전으로 과다 연결 및 동시 수정 방지. 실제 은행 금액·잔액은 보존.
- `/receivables`: 현장별·거래처별 미수·미지급과 기한 경과 목록. 업무 현황에도 별도 청구 잔액 표시.
- `/tax-summary`: 월별/분기별 확인 세금계산서 기준 추정, 공제 확인·미확인·불공제·영세·면세 구분.
- `/cash`: 은행 거래를 예정 실적에 연결, 실적 취소와 완료 해제, 남은 예정과 자금 전망 복원. 취소 이력 보존.
- 은행 분류 수정/묶음/되돌리기에서 매입·매출 및 예정 실적 연결과 내부이체의 충돌 차단.
- 상세 집계 기준과 제한은 TRADES-AND-RECONCILIATION.md, CASH-BANK-CONNECTIONS.md 참고.

### 공사별 손익계산서 및 준공 전망
- `/project-profit`: 현장별 발생원가, 남은 예상 원가, 계약 대비 준공 손익·적자 예상 표시.
- 매입 원가 구분·증빙·부가세 검토와 연결. 미지급 매입을 원가에 포함하고 은행 지급액을 중복 가산하지 않음.
- 매입 문서 외 발생원가 등록·수정·취소, 미승인 추가공사 별도 관리, 전후 변경 이력과 버전/요청 중복 보호.
- 계약·원가 기준 지문이 바뀌면 재검토 전 이익 보류. 미확인 자료·남은 원가 빈칸도 이익 계산 보류.
- `/project-profit/statement?project=...`: 해당 공사의 손익계산서만 조회·미리보기·인쇄·엑셀 저장. 관리용 준공 전망임을 출력 자료에도 명시.

### 발행어음대장과 만기 지출
- `/issued-notes`: 발행일+3개월 만기(월말·윤년 보정), 거래처/현장/결제 계좌, 검색/50건 페이지, 월별 미결제 만기 합계.
- 기존 같은 금액·만기일의 미처리 어음결제 예정 연결 또는 확인 후 신규 생성. 재전송·버전·회사 범위 보호.
- 지정 계좌의 은행 출금으로 전액 처리하면 어음/예정 동시 완료. 실적 취소 시 어음/만기 예정 복원. 등록 취소 시 지출 예정도 함께 종료.
- 은행 실제 거래·매입 미지급·공사 원가를 임의로 변경하지 않음. 수취어음·할인/배서는 아직 범위 밖. 상세: ISSUED-NOTES.md.

### 수취어음·할인 관리
- `/received-notes`: 보유·전액 추심·할인·만기 확인 상태와 액면/할인료/실입금·월별 만기 조회.
- 기존 같은 만기·금액의 예정 재사용 또는 확인 후 신규 생성. 보유 어음은 예상 입금으로 처리.
- 할인은 순입금만 실제 실적으로 반영하고 미래 액면 예정 종료. 추심/할인 실적 및 만기 확인 취소에 따른 원상 복원.
- 회사·버전·요청 중복 및 은행 연결 한도 보호. 매출채권 대체·할인료 원가 배부·세무·배서·부도는 범위 밖. 상세: RECEIVED-NOTES.md.

### 송금 준비표·정기 지급
- `/transfer-preparation`: 기한 내 미지급 매입과 확인한 정기 지급, 수취계좌별 합산·공사별 상세·선택 출력. 미확인 보류와 어음 제외. 각 원본의 지급 처리로 이동.
- `/recurring-payments`: 월세·공과금 기준, 월별 중복 없는 준비, 월별 금액 확인, 기존 매입/예정 연결 또는 확인 후 새 예정 생성.
- 거래처 지급 조건·확인 계좌·변경 이력. 일부 지급 잔액·완료 제외·취소 복원. 상세: TRANSFER-PREPARATION.md.

### 직원·계약·출역·월별 급여 검토
- `/employees`: 직원 고용 구분·기간, 적용일별 일반/신호수 단가·사무실 월 기준액과 전후 이력.
- `/work-records`: 작업일 계약으로 공수·실지급 일당 정밀 계산, 원본 메모, 수정·취소, 직원 잠금에 의한 중복/동시 저장 보호.

### 급여 지급 확인·송금·은행 실적
- `/payroll-payments`: 직원·월별 실지급액 확인, 월급제 산정 근거·일용직 조정 근거, 공수/월중 변동 확인, 중복 없는 직원 통합 지급 예정.
- 확인한 공수·계약 근거 보존. 변경 후 재확인 보류, 미지급 정정 시 과거 예정 종료·대체. 지급 실적이 있으면 급여 변경·취소 차단.
- 확인한 직원 수취계좌와 송금 준비표 연결. 부분 지급 잔액·전액 제외·실적 취소 복원. 월세·공과금과 원본 중복 연결 차단.
- 실지급액과 총 노무 원가·신고 금액은 별개. 세무·회사 부담분·손익 원가 자동 확정은 범위 밖.

# 기술 구성과 개발 원칙

## 확정한 구성

- 화면·서버: Next.js App Router + TypeScript
- 스타일: Tailwind CSS
- 데이터: PostgreSQL 17 + Prisma 7.2
- 개발: Node.js 24 LTS, npm 잠금파일, 클라우드 작업공간
- 증빙: 비공개 객체 저장소 예정. 공급자·접근제어·보관기간은 미확정

화면과 서버는 한 프로젝트로 시작한다. 한국어·원화·한국 업무 날짜를 기본으로 설계한다.
서버의 운영체제 시간대에 의존하지 않고 업무 날짜와 시각을 구분한다.
현재 화면은 DB의 기준정보·입출금 예정·실제 처리와 수기 기준잔액을 조회한다. 은행 실시간 잔액은 연동하지 않았다.

## 데이터 접근

`src/lib/db.ts`의 지연 생성 Prisma 클라이언트는 서버 코드에서만 사용한다.
공식 다운로드 도메인 접근은 환경 설정 게시 후 복구됐고 클라이언트 생성·초기 마이그레이션을 완료했다.
DATABASE_URL은 로컬 `.env` 또는 실행 환경에서 주입하고 브라우저에 전달하지 않는다.
원화 금액은 Decimal(20,0)으로 저장하며, 향후 단가·수량은 필요한 소수 정밀도를 별도 정의한다.
전북은행의 미확인 대출 한도처럼 모르는 값은 0으로 바꾸지 않고 null로 구분한다.

현재 모델은 법인·계좌·현장·거래처·입출금 예정·실제 처리·기준 잔액 이력·계좌별 실제 은행 거래를 포함한다. 실제 회사 자료는 자동 생성하지 않는다.
지급·정산은 DB 트랜잭션·버전·요청 식별자로 일관성을 보장하고 동시 처리·중복 요청을 검사한다.
현재 스키마가 완전한 회계 원장이나 거래 기능을 구현한 것은 아니다.

## 개발·배포 경계

Docker Compose는 개발용 PostgreSQL만 구동하고 DB 포트는 루프백에 바인딩한다.
운영 환경에서는 별도 비밀값·백업·TLS·인증·권한·증빙 접근제어를 구성해야 한다.
Prisma 생성 파일과 비밀값은 Git에서 제외하고 마이그레이션·잠금파일은 보관한다.
확정된 의존성은 package-lock.json을 기준으로 npm ci로 재현한다.

## 현재 구현과 후속 개발

현재 기능과 개발 순서는 [구현 상태](IMPLEMENTATION.md)를 따른다.
로그인은 단일 관리자용이며 개별 역할 권한과 운영용 인증은 후속 구현이다.
회사 설정과 기준 잔액은 각각 버전을 검사한다. 거래처·현장·계좌 수정에도 버전 검사를 적용한다.
세션 쿠키는 서명·유효기간·HttpOnly·SameSite 정책을 적용하며 로컬 HTTP와 운영 HTTPS 정책을 구분한다.
테스트는 tsx/node:test와 Playwright/시스템 Chromium을 사용한다.

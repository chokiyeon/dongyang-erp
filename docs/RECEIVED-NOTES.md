# 수취어음·할인 관리

메뉴: 자금 관리 → 수취어음·할인 관리 (`/received-notes`). 실제 받은 어음을 기록하며 금융 거래를 실행하지 않는다.

## 등록

어음을 준 거래처, 현장, 수취일, 원본 만기일, 액면금액과 사유를 입력한다. 발행어음과 달리 원본 만기를 직접 입력한다. 같은 관리번호·요청은 중복 등록하지 않는다.

만기·금액이 같은 미처리 공사대금/수취어음 입금 예정에 연결하거나, 기존에 없다는 확인 후 신규 생성한다. 보유 어음은 현금이 아니므로 예정은 ‘예상 입금’이다. 자금계획의 예상입금 포함 전망에만 반영하고 확정입금 기준 전망에서는 제외한다.

잘못 등록한 내역은 실적 취소 후 등록 취소하고 별도 관리번호로 다시 기록한다. 등록 취소는 연결된 만기 예정도 종료한다. 직접 금액·만기 수정 또는 연결만 해제하는 기능은 아직 없다.

## 추심과 할인

- 전액 추심: 수취일 이후 실제 회사 은행 입금을 액면 전액으로 연결한다. 수기·부분 처리·계좌 간 이체는 거절한다. 전액 입금 완료 상태와 실제 실적만 반영하고 원래 만기 예정은 종료한다.
- 할인: 실입금액 = 액면금액 − 할인료/은행 수수료 합계. 수취일 이후·만기 전 실제 순입금 거래를 연결한다. 할인료는 0 이상이고 액면보다 작아야 한다.
- 할인 후 자금 전망에는 실제 입금일의 순입금만 반영한다. 미래 액면 예정과 별도 수수료 출금을 다시 만들지 않는다.
- 예: 액면 1,000원, 할인료 10원 → 현금화 990원. 실제 현금화와 미래 액면 1,000원을 중복 합산하지 않는다.
- 은행 거래의 다른 예정 실적까지 포함해 초과 연결을 차단한다. 합산 입금도 연결 가능 금액 내에서 각각 나눠 연결할 수 있다.
- 할인료는 대장에 구분 표시하되 공사 원가·매입 부가세에는 자동 추가하지 않는다. 실제 원가 배부와 세무 처리는 별도로 검토한다.

부분 할인·배서, 액면 전액 입금과 수수료가 따로 출금되는 형태, 부도·환수 실적은 아직 범위 밖이다.

## 만기 확인과 복원

할인 후에는 만기 전에 환수 부담이 남을 수 있으므로 ‘할인 현금화 · 만기 확인 전’ 상태와 액면금액을 별도로 표시한다. 이는 잠재 부담을 점검할 금액이며 확정 채무나 자금 지출에 자동 반영하지 않는다.

만기 도래 후 은행 자료로 추심 완료·환수 부담 해소를 확인하고 사유와 함께 만기 확인을 완료한다. 날짜만 지났다고 자동 완료하지 않으며 추가 입출금도 만들지 않는다.

잘못한 만기 확인은 취소할 수 있다. 확인 완료 상태에서는 먼저 만기 확인을 취소한 뒤 할인 실적을 취소한다. 최근 실제 실적을 취소하면 보유 상태·원래 만기 예정이 복원되고 할인료·실입금액은 과거 변경 이력에 보관한다. 실제 은행 입금 취소·반환은 별도 업무다.

## 집계 및 보호

요약 합계는 조회 조건 전체, 목록·출력·엑셀은 현재 페이지 50건 기준이다. 월별 보유·할인 만기는 필터와 별도로 회사 전체 자료다.

회사 범위, 어음·예정·은행 연결 버전, 요청 재전송을 검증하고 한 DB 트랜잭션에서 적용한다. 은행 원본 금액·잔액은 변경하지 않는다.

매출채권을 받을어음으로 대체하거나 할인료를 포함해 매출 청구 잔액을 정산하는 회계 연결은 아직 하지 않는다. 매출·미수금·공사 이익을 임의로 변경하지 않는다. 매출 정산과 자금계획의 같은 은행 연결을 서로 더하지 않는다.

# 비은행 상계 정산 후속 구현 기준

현재는 은행 연결액만 실제 지급·수금으로 계산한다. 아래는 후속 구현 설계이며 아직 상계 등록 기능은 제공하지 않는다.

같은 회사·거래처의 확정된 반대 방향 채권·채무를 선택하고 합의 증빙, 합의일, 금액, 사유를 보관한다. 취소 환급채권과 재발급 지급채무도 별도 원본을 지정한다. 서로 다른 거래처, 미확인 원본, 마감일, 잔액 초과, 중복 요청, 후속 정산 이후 과거 해제를 차단해야 한다.

상계는 독립 원장으로 기록하며 TradeDocument.settledAmount와 TradeBankLink, BankTransaction, 은행 잔액은 변경하지 않는다. 원 청구 잔액, 환급 잔액, 자금 예정의 현금 필요액에서만 해당 상계액을 별도로 차감한다. 청구·환급·예정·송금 준비·손익의 모든 조회가 이를 함께 처리하기 전 등록을 활성화하지 않는다.

저장 시 전역 기간 잠금과 양쪽 원본 버전 확인을 같은 트랜잭션에서 수행한다. 양쪽 원장의 상계 합계를 잠금 안에서 다시 산출하고 요청 식별자를 고유하게 둔다. 해제는 원 기록을 삭제하지 않고 해제일·사유·이력을 추가한다. 월별 전달본은 합의일과 해제 효력일 기준으로 재구성해야 한다.

수정 세금계산서·취소·실제 은행 지급·환급 대조가 진행된 원본은 상계 후 남은 잔액을 사용해야 한다. 독립 원장을 넣기만 하고 기존 은행 전용 잔액 경로를 방치하면 이중 송금이나 이중 환급이 발생하므로 모든 경로를 연결해서 검증한다. 매출·매입 원가와 세액 자체는 상계만으로 변하지 않는다.

필수 검증은 부분/전액 상계, 환급과 재발급 조합, 원은행 보존, 합산·동시 요청, 낡은 버전, 해제 재시도, 마감 전후 전달본, 기존 송금 검토 승인 무효화 및 실제 후속 지급이다. 회사 실자료로 자동 상계하지 않는다.

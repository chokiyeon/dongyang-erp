# 청구 헤더와 품목 세부행 구분

같은 승인번호는 매입/매출 구분·작성일·공급자/공급받는자 사업자/종사업장·청구 합계/공급가액/세액·세금계산서 분류를 비교한다. 품목명·규격·수량·품목 단가/금액·품목 비고가 다르다는 이유만으로 청구 헤더 충돌로 보지 않는다. 같은 세금계산서의 여러 품목과 전체/월별 사본을 청구에 여러 번 합산하지 않는다. 사업자번호가 같으면 상호의 표기 차이만으로 기존 ERP 대조를 불일치로 처리하지 않는다.

이관 원본은 같은 승인번호의 세부행을 시트·행·셀 내용과 함께 보관한다. 문서 상세에서 최대 100행을 참고할 수 있고 전체 원본 파일과 회계 전달본에는 원문을 보존한다. 원본 품목 세부행은 전체/월별 사본이 섞여 있으므로 재합산하지 않는다. 품목별 수량으로 재고 입출고를 자동 생성하지 않는다.

실제 청구 헤더가 충돌하면 유효한 양수 행에 한해 발행 원문을 비교하고 선택 사유를 기록해 한 행을 선택할 수 있다. 날짜/금액 합계/셀 오류가 있는 행은 확인 체크로 강제 통과시키지 않는다. 수정 재발급이면 전액취소 관계도 필요하다. 다른 원문은 삭제하지 않고 보관하며 선택 사실과 사유는 청구 변경 이력·원본 이관 메타데이터·회계 전달본에 남긴다.

실제 회사 원본은 읽기 전용으로 구조·충돌 열을 대조했으며 DB로 자동 이관하지 않았다. 품목 차이와 청구 충돌 분리, 앞자리 0, 복수 품목 청구의 1회 집계, 유효 헤더 선택 및 오류 행 강제 통과 차단을 합성 자료로 검증했다.

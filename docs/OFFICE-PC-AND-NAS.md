# 회사 메인 PC + NAS 운영 준비

확인된 장비: 윈도우 10, RAM 8GB 메인 PC(인터넷 팩스와 함께 사용), 사진상 ipTIME NAS2dual(듀얼코어 1.6GHz·RAM 2GB). NAS는 자료·백업 보관용, 메인 PC는 ERP와 PostgreSQL 실행용으로 준비한다. 실제 CPU·디스크·윈도우 64비트 여부와 팩스 동시 부하는 설치 전 확인한다. 메모리 증설은 실사용을 확인한 뒤 판단한다.

클라우드에서 계속 개발하며 회사 사용 시 실행 환경을 메인 PC로 옮긴다. 현재 회사 PC/NAS에 원격 설치하거나 기존 자료를 변경한 상태가 아니다. 사내 전용 접속은 별도 클라우드 서버 임대를 전제로 하지 않는다.

## 메인 PC 설치 준비

- Node.js 24와 PostgreSQL 17의 지원되는 64비트 실행 환경을 준비하고, 실제 회사 업무 전용 DB·계정을 생성한다. 설치는 사내 PC 관리자와 실행 계정을 확인한 뒤 진행한다.
- `.env.office.example`을 참고해 `.env.office`를 회사 PC 안에서 설정한다. 이 파일의 비밀번호·세션 키는 Git이나 채팅에 보내지 않는다.
- 처음에는 `ERP_OFFICE_BIND=127.0.0.1`로 메인 PC에서만 시험한다. 회사 네트워크 담당자와 고정/예약된 사내 IPv4를 확인한 다음 해당 주소로 바꾼다. 사내 모드는 공인 IP나 `0.0.0.0` 전체 바인딩을 거절한다.
- `npm ci`, `npm run db:generate`, `npm run db:deploy`, `npm run build`를 설치 단계에서 검증한다. 이미 사용 자료가 있는 DB를 초기화하는 명령은 사용하지 않는다.
- 실행은 `npm run start:office`를 사용한다. 각 직원은 승인된 사내 주소로 접속한다. 메인 PC 종료·절전 중에는 접속할 수 없다. 팩스와 함께 부하·재시작·로그인·인쇄를 시험한다.
- 윈도우 보안 업데이트 상태와 회사에서 사용할 실행 계정을 확인한다. 인터넷 공개나 공유기 포트 개방은 이 구성에 포함하지 않는다.

## NAS 백업

`ERP_NAS_BACKUP_DIR`에 메인 PC 실행 계정이 접근 가능한 실제 NAS 공유 경로를 설정한다. NAS에 ERP의 실시간 DB 파일을 공유 폴더로 직접 두는 방식이 아니다. PostgreSQL은 메인 PC에서 운영하고, 완성한 백업 파일을 복사한다.

ERP ‘실행 장치·NAS 백업’에서 실행하면 먼저 로컬 `backups/office`에 PostgreSQL custom dump를 만든다. DB 안에 저장한 첨부 원본도 포함된다. 완성본만 NAS의 `Dongyang-ERP-Backups` 하위에 새 고유 이름으로 복사하고 크기·SHA256을 확인한다. 기존 회사 자료나 이전 백업을 덮어쓰거나 자동 삭제하지 않는다. NAS 실패 시 로컬 백업을 보관하고 실패 상태를 표시한다.

퇴근 전 백업 완료 메시지를 확인하고 PC를 종료한다. 백업 중 강제 종료를 피한다. 중단 후 실행 잠금이 남으면 실행 중인 백업이 없는지 관리자 확인 후 앱의 `backups/.nas-backup.lock`만 정리한다. NAS 공유 자료나 덤프를 삭제하는 절차가 아니다. 자동 시작·예약 백업은 실제 근무시간과 실행 계정을 확정한 뒤 설정한다.

첫 회사 적용 전 별도 빈 DB에서 `db:restore` 복구를 검증한다. 현재 사용 DB로 덮어쓰는 복원은 차단한다. 기존 NAS 파일을 자동으로 ERP에 이관하거나 삭제하지 않으며 원본 자료 이관은 회사 자료 대조 후 별도로 진행한다.

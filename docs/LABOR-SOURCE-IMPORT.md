# 현장 근무자료 → 급여대장

`현장 출역·공수 → 현장 근무자료 읽기·급여대장 적용`에서 파일을 선택한다. 이 기능은 명세서 파일을 대신 작성하는 도구가 아니라, 받은 근무자료를 기존 출역과 급여 검토에 연결하는 기능이다.

## 엑셀

- XLS/XLSX 현장 노임대장(성명 E열, 날짜별 공수 F~U의 위·아래 두 줄, 출역 합계 V열, 단가 W열, 총액 X열, 공제 Y~AD열, 차인지급 AE열)을 읽는다. 작업월은 표 내용으로 확인하며 파일명으로 추정하지 않는다.
- 직원·현장·일반/신호수를 연결하고 확인한 행만 적용한다. 동일 이름의 직원이 한 명이고 원본에서도 이름이 유일하면 연결 후보를 채울 수 있다. 상용직이나 동명이인을 일용직으로 자동 합치지 않는다. 이름이 다르면 별도 식별 확인을 요구한다.
- 날짜별 공수와 원본 합계가 다르거나 날짜/수식 오류가 있으면 적용을 막는다. 공제·지급액 차이는 표시하며 해당 원본으로 최종 지급액을 자동 확정하지 않는다.
- 확인한 공수는 기존 계약으로 출역에 등록한다. 원본의 **공제 전 일당**을 ERP의 **실제 지급 계약 일당**으로 바꾸지 않는다.
- 기존 출역과 공수가 같으면 원본만 연결한다. 다른 공수·이미 다른 원본에 연결한 출역·변경된 계약은 덮어쓰지 않는다. 동일 원본 재선택은 기존 연결을 유지한다. 한 행이라도 실패하면 이번 묶음 전체를 롤백한다.

## 급여 검토에 채우기

적용 결과의 `이 직원 급여 검토 → 현장 원본 지급·공제 내역 대조`를 연다. 월별 원본 일당·공제·지급액과 현재 출역을 대조한다.

`원본 지급·공제를 급여 검토에 채우기`는 입력칸만 채운다. 원본 공제항목 합계로 계산한 금액과 원본 차인지급액을 각각 표시한다. 원본 실지급액과 계산액이 다르면 최종 실지급액을 비워 두며 자동 선택하지 않는다. 항목을 대조해 수정하거나 확인한 계산액을 명시적으로 입력해야 한다. 차이/미기재가 있으면 확인 체크와 산정 근거를 기록해야 저장할 수 있다. 원 미만 금액·일당 누락·지급총액 불일치·미연결/변경 출역·같은 계약 구간의 현장별 다른 공제 전 단가는 자동 채움을 보류한다. 임의 반올림이나 고정 월급의 일당 환산을 하지 않는다.

사용자가 개별 지급·공제 내역과 지급일을 확인해 기존 급여 지급 확인에서 저장하면 기존 급여대장·급여명세서/JPG 흐름으로 연결된다. 금액을 채워도 지급 자체나 송금은 실행하지 않는다.

## 사진·PDF

PDF 쪽 선택, 원본 보기/90도 회전, 로컬 한국어/영어 글자 인식을 제공한다. OCR 엔진·언어·PDF 작업 파일은 설치한 고정 버전 패키지에서 준비하며 외부 OCR 서비스로 보내지 않는다. 손글씨의 현장 약칭·일수·신호수 표시를 임의 규칙으로 변환하지 않는다.

사진/PDF는 인식 원문을 참고해 원본 쪽·행·이름·연월·현장·날짜별 공수를 직접 대조하고 확인한 값을 적용한다. 사진의 숫자/현장 약칭을 모두 정확히 읽어 자동 등록하는 기능으로 표현하지 않는다. 공제와 공제 전 일당은 별도 급여 검토가 필요하다.

## 원본·운영

선택한 원본은 실제 적용 시 해시당 한 번 저장하고, 직원/현장별 적용 행과 출역을 연결한다. 급여 검토에서 원본을 내려받을 수 있다. 다른 월/직원 출역, 기간 마감, 계약 변경, 같은 출역의 중복 원본 연결을 검사한다. 원본 적용 후 출역을 수정/취소하면 자동 금액 채움을 보류한다. 현재는 잘못된 연결을 자동 덮어쓰지 않으며 이 경우 원본과 출역을 대조해 기존 수기 정정 절차를 따른다.

회계 전달본은 해당 월의 원본 연결·변경 상태와 원본 파일을 포함한다. 원본의 주민등록번호/계좌를 직원 생성이나 송금 계좌 확인에 자동 적용하지 않는다. 회사 실자료는 개발 DB에 자동 이관하지 않았다.

`npm run build`, `npm run build:office`, `npm run dev` 전에 OCR/PDF 파일을 `public/ocr`에 준비한다. 이 폴더는 패키지에서 재생성하므로 Git/소스 ZIP에 직접 저장하지 않는다. 설치에는 기존 npm 의존성 설치가 필요하며 설치 이후 인식은 로컬 파일을 사용한다.

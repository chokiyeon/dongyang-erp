# 미지급 청구의 기존 예산안과 수정증빙

은행 지급이 아직 없는 매입·매출도 기존 예산안에 연결한 상태에서 음수 수정세금계산서를 대조할 수 있다. 원본 검토에서 같은 달/다른 달과 전액 취소/부분 감액을 선택하고 원본 청구를 대조한다.

- 전액 취소는 원 지급 예정의 ID·금액·날짜를 보존하고 미지급 예정만 종료한다. 환급 예정이나 은행 거래를 만들지 않는다. 정식 취소 입력을 정정하면 같은 예정을 다시 연다.
- 부분 감액은 예산 금액을 수정 후 청구 순액으로 맞춘다. 입력 정정은 원금액으로 복원한다. 실제 지급이 추가됐으면 그 은행 대조를 먼저 확인해야 한다.
- 원 청구와 금액·방향·공사·확정 지급일이 다른 예산, 이미 종료했거나 다른 원본에 사용한 예정은 보류한다. 정기 지급·차량·공사 배부는 별도 검토가 필요하다.
- 감액이 유효한 동안 원 지급 예산안의 임의 분리를 막는다. 원래 예산안이 없었는지와 원래 연결 ID를 따로 기록하여 이후 해제/재연결에도 과거 월 전달본을 유지한다.
- 자재 원본은 기존 반품·단가 감액 증빙 대조를 그대로 요구한다. 입력 정정은 실제 물품 반품이나 원 은행 금액을 지우지 않는다.

DB 변경은 추가 마이그레이션 두 개다. 기존 감액의 기록 여부는 false로 유지하고 새 기록만 원 연결을 명시한다. 미지급 취소 증빙은 별도 unpaidPlanBasis에 보관하며 실제 환급의 paymentBasis/refundPlan 제약을 완화하지 않는다. DB를 초기화하지 않는다.

검증: 합성 자료의 단위/DB 189개 통과, 타입/lint/운영 빌드 통과, 54개 마이그레이션의 격리 DB 백업·복구 통과. 회사 실자료나 실제 송금을 실행한 것은 아니다. 화면 검증 결과는 재개 기록에 남긴다.

# 현장자료 읽기 개발 검증 기록

2026-11-03. 사용자 목표는 명세서 파일 대행 제작이 아니라, 받은 근무자료를 읽어 기존 급여대장에 적용하는 기능이다. 잘못 올렸다고 정정한 이전 상용직 화면은 적용하지 않았다.

## 실제 원본 읽기 확인

새로 받은 현장 전도금 XLS 3개를 읽기 전용으로 확인했다. 2026년 10월 13행/41행/13행, 총 67행의 이름·날짜별 공수·일당·지급·공제 항목을 해석했다. 현장 간에 반복된 이름/금액, 날짜별 공수와 원본 합계의 차이 1행, 공제항목 합계와 원본 차인지급액의 차이를 확인했다. 숫자와 공제를 임의로 맞추거나 회사 실자료를 개발 DB의 직원·급여로 자동 생성하지 않았다. PDF 4쪽은 스캔 근로일지이며 날짜별 현장 약칭을 숫자 공수로 확정하지 않았다.

## 개발 환경

환경 접속 중단 뒤 작업 파일과 원본 첨부가 남아 있는 것을 확인했다. PostgreSQL 컨테이너가 중지되어 기존 컨테이너를 시작했으며, 기존 데이터 디렉터리의 자동 복구 완료 후 연결·마이그레이션·관계 조회 검증을 통과했다. 자료 초기화나 새 DB로의 회사자료 덮어쓰기를 하지 않았다.

## 검증된 흐름

- XLS/XLSX의 2줄 출역 판독, 원본 금액·차이·누락·원 미만 금액 보존.
- 같은 원본 재선택/재시도 중복 방지, 기존 출역 재사용, 원 계약 단가 보존, 합계 오류/상용직 혼합 묶음 전체 롤백.
- 공수 적용 → 원본 지급/공제 검토 채움 → 차이 확인/산정 사유 → 기존 급여 확인/급여명세서.
- 원본 다운로드의 바이트 일치와 회계 전달본 ZIP의 원본 포함.
- PDF 렌더링 → 한국어/영어 로컬 OCR → 원문 확인 → 날짜별 공수 직접 대조/등록. 외부 HTTP OCR 전송 없음.
- 원본/출역 변경 시 검토 초안 보류 및 적용 기준 해시 변경.
- 새 원본 스키마를 포함한 별도 DB 백업/복구·첨부 바이트·20자리 금액·마이그레이션 체크섬 보존.

최종 전체 단위/DB 검사 130개 통과 (`/tmp/labor-release-all-tests.log`), 49개 마이그레이션을 포함한 백업/복구 통과 (`/tmp/labor-release-backup.log`). 출역·명세서·회계 전달 화면 4개 흐름 통과 후, 같은 원본 행의 현장별 분리 및 차이 금액 확인 동작을 보완하고 원본 가져오기/PDF 화면 2개를 재검증했다 (`/tmp/labor-finalize-browser.log`, `/tmp/labor-final-browser3.log`). 타입·lint·운영 빌드 통과 (`/tmp/labor-final-types3.log`, `/tmp/labor-final-lint3.log`, `/tmp/labor-final-build3.log`). 회사 PC의 실제 설치·사내 브라우저 성능·NAS 접근/복구·실제 직원 코드 매핑은 아직 운영 검증 전이다.

## 보류한 다른 작업

기지급 전액취소·환급 초안은 사용자의 현장 근무자료 요청을 우선 처리하면서 `docs/in-progress`에 보존했다. 실행 경로에서 분리했으며 환급 개발 완료로 표현하지 않는다. 이미 적용된 추가 스키마는 유지하고 이전 마이그레이션을 수정하지 않는다.

# 매입매출 원본 검토

`/trades/review`에서 회사의 매입매출 원본 XLSX를 브라우저 안에서 검토한다. 서버에 원본을 전송하거나 거래처·청구·수금·지급을 생성하지 않는다. `2026년.xlsx`의 전체 매입/매출 및 월별 출/입 시트 형식을 기준으로 구현했으며 시트명과 세금계산서 머리글을 함께 확인한다.

## 검토 상태

- 추가 검토 후보: 기본 날짜·승인번호·원 단위 금액 합계 검사를 통과했다. 실제 등록 가능 확정이 아니며 거래처/공사 매핑과 기존 ERP 중복 검토가 더 필요하다.
- 파일 내 중복: 같은 승인번호의 주요 거래정보·품목 내용이 같은 행이 파일 안에 반복된다. 최초 원본 시트/행을 표시하고 중복 합산하지 않는다. 후반부 결재일·메모 등 원본 확장 열은 각각 보존한다.
- 확인 필요: 같은 승인번호의 구분·금액·품목 차이, 수정/취소 종류, 음수/0원, 날짜 오류/미래일, 승인번호 미입력·숫자 저장, 합계 불일치, 수식 결과 누락·셀 오류 등을 표시한다. 수정세금계산서를 일반 양수 청구로 바꾸지 않는다. 수식은 실행하지 않는다.

인식하지 못한 시트는 목록으로 알리고 자동 해석하지 않는다. 파일 내 비교이며 기존 ERP의 등록 문서와 자동 대조하는 단계는 아직 아니다. 승인번호가 없는 행을 금액/이름만으로 임의 병합하지 않는다.

## 검토표 저장

`검토.xlsx`는 안내·원본 SHA256, 전체 검토 결과, 인식한 각 시트의 원본 행번호/열 이름/셀 내용을 담는다. 화면은 100행 단위와 상태 필터를 제공하지만 검토표는 필터와 관계없이 전체를 포함한다. 거래 식별 열이 비어 있는 메모 행도 원본 시트 사본에 남긴다. 텍스트·앞자리 0·큰 금액은 문자열로 내보내고, 수식/오류 등 구조화 셀은 JSON 텍스트로 남겨 실행하지 않는다. 서식까지 같은 원본 파일 자체를 재생성하는 기능은 아니므로 원본도 계속 보관한다.

현재 한 파일은 10MB, 인식 시트당 15,000행·100열, 파일의 비어 있지 않은 데이터/메모 행은 30,000행까지 검토한다. 사내 HTTP에서도 SHA256을 계산할 수 있다. 읽기 전용 실제 회사 원본 검토 외에는 합성 자료로 테스트하며 원본 거래행·개인정보를 저장소에 포함하지 않는다.

## 다음 단계

검토 후 기존 ERP 문서 대조, 거래처·공사 연결, 수정 원본과의 관계 및 음수 정정 정책, 원본 필드 보존을 갖춘 실제 이관 절차가 필요하다. 현재 화면을 실제 이관 완료로 표현하지 않는다.

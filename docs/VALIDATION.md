# 검증 기록

최근 검증일: 2026-10-31 (한국 시간)

## 현재 구현 검증

- Prisma 스키마 검증·클라이언트 생성·마이그레이션 적용 완료
- `npm run typecheck` 통과: 라우트 타입 생성 후 TypeScript 전체 검사
- `npm run lint` 통과
- `npm test`: 17개 통과, 실패·건너뜀 없음
- `npm run build` 통과
- `npm run test:e2e`: Chromium에서 전체 업무 흐름 1개 시나리오 통과
- `git diff --check` 통과

서버·DB 검증 범위:
- 20자리 원화 금액 정밀도, 0원/미확인 구분, 잘못된 금액·날짜 거부
- 회사·복수 대표, 거래처·현장·계좌 저장과 관계 조회
- 다른 회사 발주처 연결 거부, 중복 코드 거부, 동시 수정 충돌·사용 중지
- 일부 지급, 예정과 다른 최종 정산·사유 필수, 남은 예정액 계산
- 같은 요청 재전송 시 이중 계상 방지, 완료 건 추가 지급 거부
- 수금 없이 정산 완료·예정 초과 처리 검증
- 기준일 이전 실적 제외, 확정/예상 입금 시나리오, 지난 예정의 이월 가정
- 음수 기초잔액·월말·연도 전환·기준 잔액 변경 충돌과 이력 보존

브라우저 검증 범위:
- 비로그인 접근 차단, 잘못된 비밀번호 안내, 로그인·로그아웃
- 회사 등록, 거래처 등록·중복 안내, 현장 등록·상태 수정
- 1,000만 원 예정 → 600만 원 지급 → 최종 950만 원 정산 → 잔여 예정 0원
- 정산 사유 누락 안내 후 금액과 최종 완료 체크 유지
- 2,000만 원 기준잔액에서 950만 원 지출 후 1,050만 원 전망 확인, 6개월 전환
- 계좌 한도 미확인 표시, 음수 한도 거부, 0원 한도 저장
- 실제 브라우저 런타임 오류 없음, 모바일 390px에서 페이지 수평 넘침 없음
- 시험용 가상 데이터의 데스크톱·모바일 화면 육안 확인

DB 테스트는 롤백한다. 브라우저 테스트는 고유 코드로 생성한 자료만 삭제한다.
실제 은행 파일이나 급여·주민등록번호·계좌번호는 사용하지 않았다.

## 과거 환경 문제와 해결

`binaries.prisma.sh` 접근 403은 사용자 환경 설정 게시 후 해소됐다.
현재 정책 적용과 실제 Prisma 다운로드·실행을 확인했고 TLS·체크섬 검증을 유지했다.
초기 정적 화면 시점의 PostgreSQL 직접 연결 검증은 이후 Prisma·업무 통합 검증으로 확장했다.

## 남은 범위

은행별 실제 엑셀 양식, 매입·급여·어음 등 후속 모듈과 운영 배포는 검증하지 않았다.
현 단계 검증은 완성된 ERP의 회계 정확성·세무 신고 적합성·운영 보안 인증을 의미하지 않는다.
현재 기능과 한계는 [구현 상태](IMPLEMENTATION.md)를 참조한다.

### 원본 예산안 배치 반영

업로드된 예산안의 A:I 영역을 확인해 상단 현금·통장 / 보유어음, 하단 좌측 입금 / 우측 지출 / 마지막 잔액 구성으로 `/forecast`를 재배치했다. 원본 금액과 계좌정보는 가져오지 않았다. 통장 현황은 등록 계좌의 장부상 최근 잔액·기준일을 참고로 표시하며, 확인한 기준 가용현금과 구분한다. 계좌번호 필드가 없는 현재 계좌정보는 별칭으로 표시한다. 보유어음 액면을 현금에 합산하지 않는다.

좌우 상세는 같은 날짜끼리 배치한다. 중간 행에 임의의 잔액을 붙이지 않고 해당 날짜 마지막 행에 일말 잔액을 표시한다. 원예정일 경과, 실제·확정예정·예상예정, 부분 지급 잔액을 구분한다. 월말 예상입금 포함 잔액은 별도 표시한다. 거래 없는 달도 잔액을 이월한다. 항목 선택 시 기존 입출금 처리 화면으로 이동한다. 원본의 수기 행 순서와 무관하게 실제 자금계산은 날짜 기준을 유지한다.

가상 자료로 상세 금액과 기존 전망의 일별 입출금 합계 일치 및 부분 지급·취소·정산 완료를 검증했다. 원본 첨부파일은 변경하지 않았다.

### 원본 장부 배치 반영

기존 첨부 장부의 2026년 시트 상단과 열 구성을 확인했다. `/ledger` 상단에 통장별 현황(계좌 코드·은행·별칭·장부 참고잔액·잔액일·기간 입출금 합계)을 두고, 거래표는 날짜·거래 회계코드·은행·계좌·내역·차입금 입금·일반 입금·출금·해당 계좌 잔액·비고로 배치했다. 회계코드는 은행 앞에 유지한다. 기본 정렬은 오래된 날짜부터이며 최신순을 선택할 수 있다. 분류 수정 링크는 조회 조건·정렬·페이지를 유지한다.

차입금/일반 입금은 한쪽 열에만 표시한다. 지정된 거래 계정이 있으면 2050·2060을 따르고, 계정이 없는 기존 자료의 원본 차입금 열은 원본 분류로 보존한다. 거래 후 통장 잔액과 여러 계좌를 함께 계산한 회사 순잔액은 구분한다. 원본의 누적잔액을 은행 잔액으로 임의 전환하지 않는다. 통장 참고잔액은 조회 종료일까지 마지막으로 등록된 잔액으로, 조회 조건별 순입출금과 구분한다. 원본 파일과 은행 거래 금액은 변경하지 않았다.

최종 확인: 예산 집계·기준잔액 테스트 4건, 원본형 예산안·통합 장부 브라우저 테스트 2건 통과. 브라우저에서 부분 지급 금액, 차입금/일반 입금 열 분리, 기본 정렬, 예산안 미리보기·엑셀, 6개월 집계와 모바일 가로 넘침을 확인했다. lint·타입 검사·프로덕션 빌드 및 확대 화면 전환 검증 통과. 확대 미리보기에는 예산안과 장부를 첫 두 화면으로 추가했다.

### 원본 급여대장 배치 반영

첨부 급여 파일의 임금대장 및 노무 지급대장 머리글을 확인했다. `/payroll-review` 상단에 인적사항·근태/계약·지급·공제 확인·은행/계좌·비고 순서의 임금대장을 추가했다. 확인한 최종 지급액과 실제 지급액·남은 지급액을 구분한다. 월급제 계약액을 실지급액으로 확정하지 않으며, 일용직 실지급 일당에서 세금·보험료를 자동 재차감하지 않는다. 공제 항목별 금액이 없는 경우 별도 확인으로 표시한다. 지급 확인 후 출역·계약이 변경된 경우 재검토 표시를 유지한다.

날짜별 노무비 지급대장은 실제 월 일수에 맞춰 공수를 표시하고 현장·일반/신호수·적용 일당별로 행을 나눈다. 합산 공수와 실지급 기준액은 기존 출역 스냅샷으로 계산하며, 사무실 월급제는 출역표에서 제외한다. 가로 이동 중에도 성명을 고정한다. 원본 주민등록번호·주소·실제 급여는 가져오지 않았다. 기존 직원별·현장별·사무실 월급 검토표도 유지했다.

lint·타입 검사·프로덕션 빌드 통과. 기존 급여 브라우저 검증 1건 통과: 일반/신호수와 여러 현장 합산, 계약 변경 재검토, 새 원본형 표의 날짜 열·단가, 5개 표 엑셀 출력, 프린트, 최종 지급·은행 연결 및 원가 확인 흐름을 가상 자료로 확인했다.

### 상용직·일용직 급여대장 분리

상용직(현재 월급제 사무실 직원)과 일용직을 각각 별도 임금대장 표로 분리했다. 상용직에는 월 계약 기준액, 일용직에는 공수·실지급 일당을 표시한다. 상단 전체/상용직/일용직 선택에 따라 관련 대장과 보조표만 표시하며, 월 조회 시 선택 구분을 유지한다. 개별 대장을 선택하면 미리보기·프린트·엑셀에도 선택한 구분만 포함한다. 전체 보기에서는 6개 표를 각각 다른 제목으로 내보낸다. 원본 자료와 급여 계산·지급 확인 데이터는 변경하지 않았다.

분리 검증: 상용직·일용직 직원이 각 대장에 섞이지 않음, 구분 전환, 상용직 단독 미리보기와 2개 표 엑셀, 전체 6개 표 엑셀·인쇄 및 기존 급여 흐름 브라우저 검증 통과. 출력 검증은 화면 로딩 완료 후 실행하도록 보완했다. lint·타입 검사·프로덕션 빌드 통과. 확대 미리보기 첫 두 화면을 상용직·일용직으로 갱신했다.

### 사용자 확인한 8월 급여 양식 재반영

사용자가 `급여 8월`은 상용직, 뒤 세 시트는 일용직이라고 확인했다. 실제 8월 네 시트의 머리글과 병합 구성을 다시 확인했다. 상용직은 21열의 수당·근태·제세공제·실수령액을 위/아래 두 줄로 표시하고, 일용직 날짜는 16열의 위 1~15일/아래 16~31일로 배치했다. 없는 수당/공제 금액은 미입력으로 두며 월 계약액을 기본급·총액으로 대체하지 않는다. 일용직의 실지급 기준액을 신고용 총액으로 변환하거나 세금을 재차감하지 않는다. 신고/현장 시트의 원본을 실제 지급으로 자동 합산하지 않았다. 실제 자료는 DB에 가져오지 않았다.

가상 자료 브라우저 검증 1건 통과: 두 줄 항목·날짜 배치, 상용/일용 대상 분리, 공수·단가 계산, 계약 변경 검토, 개별/전체 미리보기·엑셀·인쇄, 최종 지급·은행 연결 흐름. 복합 머리글은 엑셀에서 `기본급 / 직무(업무)수당`, `1일 / 16일`처럼 대응을 보존한다. lint·타입 검사·프로덕션 빌드 및 확대 화면 생성 검증 통과. 세부 수당/공제 입력·신고 계산은 아직 구현되지 않았으며 이번 수정은 양식 재배치다.

### 상용직 수당·공제 입력과 대장 반영

세부 금액 입력, 지급총액/공제합계/실수령액 합산, 최종 지급액 불일치 차단, 저장된 내역의 임금대장 반영을 구현했다. 합계는 BigInt 원 단위이며 빈칸·음수 일반 항목·소수·범위 초과를 거부한다. 연말정산 조정만 환급/추가공제를 구분하는 부호를 허용한다. 계약 월급을 기본급으로 자동 채우지 않는다.

합성 사례: 지급항목 3,200,000원 − 근태공제 30,000원 = 지급총액 3,170,000원, 제세/기타공제 404,000원, 환급 조정 5,000원 → 실수령액 2,771,000원. 계산/DB 테스트 3건 통과(환급/추가공제, 경계값, 중복 요청, 감사 이력, 세부 생략 덮어쓰기 차단, 지급 후 변경 제한 포함). 브라우저 급여 검증 1건 통과(잘못된 지급액 거부, 입력 유지, 저장 후 재조회, 대장/엑셀 출력, 기존 일용직 지급·은행 연결·원가 확인). lint·타입 검사·프로덕션 빌드 통과. 실제 업로드 자료와 기존 DB 스키마는 변경하지 않았다.

### 일용직 공수 묶음 입력 및 급여 역산 계산기

신규 출역을 월별로 입력하는 화면과 원자적 저장을 추가했다. 기존 출역 덮어쓰기 차단, 계약 날짜별 단가, 중복/동시 요청, 묶음 전체 롤백을 검증했다. 급여 계산기는 확인 공제액 또는 가정한 합산 공제율/고정공제액 기준으로 세후→세전을 계산한다. 범위·정수·원 단위 최솟값을 검증하며 법정 요율은 임의 적용하지 않는다.

관련 계산/DB 테스트 6건 통과. 기존 상용·일용 급여, 지급/은행 연결과 함께 브라우저에서 공수 일괄 등록·기존 날짜 비활성화 및 세후 250만원/10% 가정 역산·조건 변경 시 결과 초기화를 확인했다. 실제 자료는 사용하지 않았다. 타입 검사·lint·프로덕션 빌드 통과.

### 원본형 급여대장 XLSX 다운로드

상용직 두 줄 수당/공제 배치와 일용직 16열 두 줄 날짜 배치의 전용 XLSX를 추가했다. 병합 셀·인쇄 방향/용지·반복 머리글·고정 행열을 설정하고, 일용직 개인 지급 합산을 별도 시트로 구분했다. API는 회사 소유 월 자료를 동일 읽기 스냅샷으로 조회하며 로그인 필수·캐시 금지다. 실제 자료를 가져오지 않고 현재 등록 자료를 내보낸다.

관련 계산/DB/워크북 테스트 7건 통과. 15자리 초과 금액 문자열, 윤년 2월 날짜 빈칸, 회사 이름의 수식처럼 보이는 문자열이 수식으로 실행되지 않음, 인쇄 설정과 원본형 머리글을 확인했다.

브라우저 검증 1건 통과: 전용 상용직 파일의 I7 기본급·M8 식대·O7 지급총액·S8 공제계·T8 실수령액과 A7:A8 병합을 확인했다. 일용직 E5/E6의 1일/16일, T6의 31일 및 개인 합산 계산액을 실제 다운로드로 확인했다. 잘못된 조회월은 400, 비로그인 요청은 로그인 리다이렉트로 차단했다. 기존 상용·일용 지급·은행 연결·공수 일괄·역산 흐름도 통과했다. lint·타입 검사·프로덕션 빌드 통과. 가상 자료 샘플 XLSX 두 개를 artifacts에 생성했다.

### 직원별 급여명세서 검토

급여 지급 확인 건별 페이지를 추가했다. 지급 스냅샷을 사용하며 현재 계약/출역 변경 시 재검토를 표시한다. 소유 회사/직원 기준을 확인하고 현재 수취계좌는 일부만 표시한다. 검토용 출력과 실제 교부를 구분한다.

관련 계산·DB·워크북 테스트 6건 통과. 저장 일당과 계산액, 잘못된 날짜·중복 출역·다른 직원/기간 스냅샷 차단, 상용직 실수령액 대조와 계좌 마스킹을 확인했다. lint·타입 검사·프로덕션 빌드 통과.

브라우저 검증 1건 통과: 상용직 명세서의 저장 수당/공제/실수령액, 인쇄 및 다른 직원 코드 제외, 일용직 계약 변경 후 경고와 저장 당시 200,000원 일당 유지(현재 220,000원), 기존 급여 저장·엑셀·지급/은행 연결·원가 확인을 검증했다. 테스트의 변경 경고 선택자는 Next 접근성 알림과 구분하도록 업무 영역으로 한정했다. 가상 자료 PDF를 생성해 본문에 검토용·기본급·실수령액이 있고 다른 직원 코드가 없는지 확인했다. 실제 교부나 외부 전송은 수행하지 않았다.

### 첨부 양식 기반 한 장 명세서·직원별 JPG

사용자 PDF 첫 장의 지급/공제 좌우 배치와 색상을 참고해 명세서를 재구성했다. 첨부의 추가 빈 페이지/다른 직원 목록은 새 파일에 포함하지 않았다. 상용직 수당/공제 항목을 모두 표시하고 미확인 금액은 임의 0으로 바꾸지 않는다. 일용직도 같은 양식과 개별 이름 JPG를 지원한다. 지급 확인/은행 실적 데이터는 변경하지 않는다.

관련 계산·DB·워크북 테스트 6건 통과. 개별 XLSX 한 시트·한 장 인쇄 범위·정확한 직원명·미확인 항목·파일명 치환 검증. 브라우저 검증 1건 통과: 전용 엑셀 다운로드, 근로자명 JPG 파일명/JPEG 서명, 상용직/일용직 각각 PDF 실제 페이지 수 1, 다른 직원 자료 제외, 원래 급여/공수/지급·은행 연결 흐름. PDF 정보로 두 파일 모두 A4 세로 1쪽임을 재확인했다. JPG 두 파일은 각각 1240×1754이며 가상 자료 샘플은 약 200~225KB이다. lint·타입 검사·프로덕션 빌드 통과.

JPG 렌더링은 브라우저의 html-to-image 1.11.13을 사용하며 실제 직원에게 발송하는 동작은 수행하지 않는다.

### 일용직 일당·일수 전용 명세서 수정

지급 쪽을 일당/일수 두 항목으로 한정하고 지급총액 − 공제합계 = 실지급액으로 연결했다. 공제 전 일당·항목별 공제 금액을 일용직 지급 확인에서 저장한다. 출역의 기존 실지급 기준 일당과 별도이므로 과거 계약 일당에서 공제를 다시 차감하지 않는다. 실제 급여·계약 자료를 일괄 변환하지 않았다.

관련 계산·DB·워크북 테스트 8건 통과. 일반/신호수 및 소수 일수 합산, 공제 후 실지급액, 원 미만/누락/과다 공제 거부, 최종 지급액 불일치·내역 생략 덮어쓰기 방지, 요청 재시도를 확인했다. 일용직 XLSX에는 기본급 없이 일당/일수만 들어가며 일수는 화폐가 아닌 텍스트로 보존한다. 일반·신호수 일당 문자열이 공제 열을 침범하지 않게 줄바꿈을 검증했다.

브라우저 검증 1건 통과: 일용직 지급 항목이 일당/일수 두 개뿐이고 기본급·식대가 없는지 확인했다. 공제 전 일반/신호수 일당을 저장해 580,000−120,000=460,000원, 계약/출역 대조 후 620,000−120,000=500,000원으로 정정해 은행 실적까지 연결했다. 최종 지급 완료 상태의 JPG·XLSX·PDF 샘플을 생성했다. 일용직 Excel A7/A8 일당/일수 및 B15/D16 지급총액/실지급액을 확인했고, 최종 PDF는 A4 세로 1쪽이다. 상용직·기존 급여·공수·역산·원본형 엑셀 검증도 통과했다. 실제 업로드 자료는 변경하지 않았다. lint·타입 검사·프로덕션 빌드 통과.

# 매입매출 원본 행 이관

매입매출 검토 화면에서 기본 검토를 통과한 행을 선택하고 거래처·공사·과세 구분·관리번호·기한·사유를 확인해 청구로 가져온다. 파일 전체를 자동 등록하는 기능은 아니다. 수정·음수·파일 내 중복/충돌 행은 이관 대상에서 제외한다. 수정/음수 업무 처리는 별도 미완료 범위로 남긴다.

서버가 원본 XLSX를 다시 읽어 날짜·승인번호·금액을 결정한다. 화면에서 보낸 금액을 등록값으로 신뢰하지 않는다. 기존 회사 범위, 거래처/공사 유효성, 승인번호 중복, 월마감 보호는 일반 청구 등록과 같은 경로를 사용한다. 동시 충돌이 나면 트랜잭션을 취소하며 같은 요청의 재시도는 최초 문서로 연결한다. 다른 요청으로 같은 원본 행을 다시 가져오면 기존 이관 안내를 표시한다.

수금/결재일과 비고만으로 실제 은행 실적·결제·자금계획을 만들지 않는다. 매입세액은 확인 필요 상태로 시작하고 발행 원본 확인 여부는 사용자가 별도로 입력한다. 기존 은행 실적·예산안 연결과 공사별 배부는 등록 후 해당 기존 기능에서 확인한다.

## 원본 보관

원본 파일은 회사별 SHA256 기준 한 번만 저장하고 문서에 원본 시트·행·머리글·셀 내용과 등록 사유를 연결한다. 앞자리 0과 확장 메모를 보관한다. 해당 문서에서 원본을 다시 내려받을 수 있고 파일 무결성을 확인한다. 원본 양식 화면은 저장한 원본의 미보존 열을 표시하면서 ERP의 현재 금액·은행 대조를 우선 표시한다. 원본의 수금/결재 표기는 비고에 ‘은행 별도 대조’로 구분한다.

회계 전달본은 해당 월 문서의 원본 행 내용을 보관하고, 첨부 ZIP에 전체 원본 XLSX를 파일당 한 번 포함한다. 전달본 생성 당시 체크섬/크기와 현재 보관 원본을 비교해 무결성이 맞지 않으면 다운로드를 보류한다. 회사 원본 파일은 저장소에 포함하지 않는다.

실제 회사 자료를 개발 DB에 자동 이관하지 않았다. 구현·검증은 합성 파일로 진행했다. 회사 PC 설치와 원본 전체 대조는 별도 미완료다.

거래처에 원본과 같은 사업자등록번호를 먼저 확인·등록해야 한다. 지급기한/지급방법은 거래처 설정을 적용하거나 직접 확인할 수 있다. 자세한 변경 이력과 검증 기준은 PARTNER-BUSINESS-IDENTITY.md를 따른다.

일반 과세 청구는 같은 사업자번호·구분끼리 최대 100건 공통 조건으로 묶음 이관할 수 있다. [묶음 이관 안내](TRADE-WORKBOOK-BATCH.md). 수정·0세액·충돌은 개별 검토한다. 화면에서 선택한 원본 해시와 실제 업로드도 대조한다.

# 거래처 사업자번호와 원본 연결

거래처에 선택 사업자등록번호를 보관한다. 전각 숫자·공백·하이픈을 정규화하되 앞자리 0을 유지하며 숫자 10자리 형식만 확인한다. 국세청 등록 상태·휴폐업·실재 여부를 자동 확정하지 않는다. 기존 거래처 번호는 비어 있는 상태로 유지하며 원본 확인 없이 채우지 않는다.

사업자번호 등록·변경·삭제 시 사유와 전후 번호를 보관하고 거래처 수정 화면에서 최근 이력을 볼 수 있다. 과거 번호와 같은 법인의 지점/별도 관리 거래처가 있을 수 있으므로 번호만으로 거래처를 자동 병합하거나 하나의 거래처로 강제하지 않는다.

## 계좌 확인과 이관

기존 거래처의 번호를 변경하면 송금 계좌 확인을 보류하고 기존 은행/계좌/예금주는 그대로 보관한다. 새 사업자 정보와 계좌를 대조한 뒤 송금정보 변경 사유를 남기고 확인해야 한다. 신규 거래처의 번호와 계좌를 함께 확인해 등록하는 경우는 별도다. 다른 수정 양식이 사업자번호 필드를 생략하면 기존 번호를 지우지 않는다.

매입매출 원본 이관은 선택 거래처에 확인된 번호가 있어야 하고 원본 공급자(매입)/공급받는자(매출) 번호와 일치해야 한다. 이관 중 월마감 잠금을 먼저 확보하고 거래처 행을 잠가 번호 확인과 청구 등록 사이의 변경 경합을 막는다. 거래처 번호가 없거나 다른 원본은 이관하지 않는다. 같은 번호의 관리 거래처가 여러 개면 사용자가 사업장·공사를 직접 확인해 선택한다.

파일 내 검토와 기존 ERP 대조는 별개다. 기존 ERP 대조에서는 원본에 번호가 있을 때 현재 거래처 번호와 비교해 미등록/차이를 알린다. 회계 전달본은 현재 거래처 번호와 이관 원본 번호를 구분해 보관하므로 번호 정정 후에도 원본 번호와 과거 전달본이 바뀌지 않는다.

## 지급 조건

원본 이관에서도 거래처의 다음 달 말일/즉시 지급 조건과 지급방법을 적용하거나 직접 기한을 입력할 수 있다. 계산된 기한을 화면에서 확인하고 공사 원가 구분·본사 공통 여부를 선택한다. 기한과 지급방법을 정하는 것만으로 은행 실적이나 자금계획을 자동 생성하지 않는다. 모르는 원가/공제 구분을 원본 품목명만으로 자동 확정하지 않는다.

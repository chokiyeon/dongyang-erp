# 매입매출 원본 묶음 이관

`매입·매출 → 원본 검토`에서 엑셀을 선택하고 `일반 과세 청구 묶음 이관`을 펼친다. 첫 행을 선택한 뒤 같은 사업자번호·매입매출 구분의 후보를 최대 100건씩 모을 수 있다. 원본 엑셀 배치와 개별 이관은 유지한다.

- 정상 검토 후보 중 양수 세액인 일반 과세 청구만 지원한다. 영세율·면세·0세액·수정·금액 충돌은 개별 검토한다.
- 거래처는 원본 사업자번호와 매입/매출 역할이 일치해야 한다. 같은 번호로 등록한 거래처가 여러 개면 직접 선택한다.
- 공사·원가 구분·본사 공통 여부·지급 조건을 공통 적용하므로 다른 현장이나 조건의 청구는 나누어 처리한다.
- 다음 달 말일은 각 계산서 작성일 기준이다. 10월 청구와 11월 청구를 함께 골라도 각각 11월 말일과 12월 말일이 된다. 직접 기한은 선택한 청구 모두에 같은 날짜를 적용한다.
- 원본 확인과 묶음 공통 조건 확인은 별도다. 부가세 공제 검토는 `PENDING`으로 남는다. 계좌 생성·은행 지급·자금예정은 자동 실행하지 않는다. 원본의 결재일 표시는 실제 지급으로 자동 인정하지 않는다.
- 관리번호는 원본 해시·시트·행으로 자동 생성한다. 원본 파일은 회사 내 해시당 한 번 저장하고 각 문서가 선택 행과 품목 세부행을 참조한다.
- 같은 요청 재시도는 같은 결과를 반환한다. 같은 원본을 새 요청으로 골라도 기존 연결을 유지한다. 다른 파일의 같은 승인번호는 주요항목 일치 시 기존 유지, 차이나 취소 이력이 있으면 대조 보류한다. 기존 자료는 덮어쓰지 않는다.
- 새 청구의 유효성 검사가 하나라도 실패하면 이번 묶음에서 생성한 새 청구와 원본을 모두 롤백한다. 기존 유지·대조 보류는 오류가 아닌 개별 처리 결과다.
- 화면의 처리 결과와 `처리.xlsx`에 원본 파일명·SHA256·시트·행·상태·문서 경로를 남긴다. 결과는 해당 브라우저 세션 기준이며 영구 업무 이력은 각 문서의 원본/변경 이력을 확인한다.

서버는 클라이언트 금액을 신뢰하지 않고 업로드한 원본을 한 번 다시 읽는다. 화면에서 계산한 원본 SHA256도 대조한다. 한 묶음은 최대 100건·같은 사업자·같은 매입매출 구분으로 제한한다. 원본 파일 10MB와 압축 해제량 제한, 기간 마감, 사업자번호 대조, 승인번호 중복 보호를 유지한다.

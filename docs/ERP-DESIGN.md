# 동양계전 ERP 업무·화면·데이터 설계 초안

작성일: 2026-10-30 (한국 시간)
상태: 사용자 대화에 따른 요구사항 초안. 구현·세무 검증 완료를 의미하지 않는다.

## 1. 목적과 범위

전기·계장·태양광·풍력 공사를 수행하는 단일 법인의 경리 업무를 중심으로 설계한다.
목표는 동일한 거래를 여러 장부에 반복 입력하지 않고, 현장 원가와 회사 자금을 연결하는 것이다.

- 회사 자금: 향후 3~6개월의 날짜별 입출금, 예상잔액, 부족 예상일 확인.
- 현장 원가: 자재비·인건비·외주비·현장경비와 미배분 비용 확인.
- 지급·수금: 예정과 실제를 연결하고 일부 처리·잔액·변경 이력 관리.
- 확장 범위: 급여, 어음, 자재 이동, 차량, 세금 추정, 회계사무소 전달 자료.
- 공무 업무 전반과 전자 신고·은행 이체 실행은 이번 설계의 구현 범위로 확정하지 않는다.

## 3. 거래 처리 원칙

### 비용·채무·지급의 구분

매입으로 발생한 비용·채무와 실제 지급을 별도로 저장한다.
매입 1,000만 원 중 600만 원을 지급하면 원래 매입은 유지하고 잔여 채무는 400만 원이다.
세금계산서 연결, 이체 연결, 어음 발행은 같은 매입을 다시 비용으로 만들지 않는다.
어음 지급은 매입채무를 지급어음으로 전환하고 만기에 은행 출금과 연결한다.

### 예정과 실제의 연결

- 예정액을 덮어쓰지 않고 원래 금액·변경 이력·실제 처리액을 보관한다.
- 미처리 / 일부 처리 / 완료 / 취소 상태를 관리한다.
- 일부 지급 후 남은 금액을 지급할 것인지, 최종 금액이 줄어든 것인지 구분한다.
- 최종 정산 차이는 사유와 함께 기록한다. 채무 자체의 감액은 별도 조정 근거가 필요하다.
- 은행 거래와 예정 내역은 다대다로 연결할 수 있다.
- 지급 예정일이 지난 미처리 건을 삭제하지 않고 재예정일과 지연 상태를 기록한다.

### 자금계획 계산

기준 시점의 실제 계좌 잔액 + 이후 예상 입금 - 이후 예상 출금으로 전망한다.
기준 잔액에 이미 포함된 실제 거래는 다시 더하거나 빼지 않는다.
실제 입출금을 반영한 뒤 남은 미처리 예정액만 미래 전망에 사용한다.
확정 입금만 반영한 전망과 예상 입금까지 포함한 전망을 구분한다.
날짜 안의 처리 순서가 불명확하면 일중 자금 충분 여부를 단정하지 않는다.

계좌의 양수 잔액·마이너스 사용액·미사용 한도·통합 순잔액을 구분한다.
미사용 대출 한도를 현금으로 표시하거나 순잔액과 중복 차감하지 않는다.
별도 관리·사용 제한 자금은 가용성 여부를 따로 기록한다.
회사 계좌 간 이체는 계좌별 흐름에는 표시하되 회사 전체 수입·비용에서 제외한다.

### 현장 원가와 손익

- 현장에 귀속되는 공제 전 노무비와 관련 회사 부담 비용을 원가로 관리한다.
- 사무실 월급제 급여는 본사 공통비로 관리한다.
- 창고 미출고 재고를 특정 현장의 비용으로 임의 배분하지 않는다.
- 현장 반입·사용·잔여 재고를 구분한다. 현장 반입액과 회계상 소비 원가를 동일시하지 않는다.
- 미사용 자재 이동은 수량·원가를 함께 이전하고 이중 비용을 방지한다.
- 손익 금액은 공급가액을 기준으로 하되 불공제 부가세 등 원가 포함 여부는 회계 기준 확인이 필요하다.
- 최종 예상이익 = 변경 반영 계약 공급가액 - 예상 총원가. 관리용 전망이며 회계 매출 인식과 구분한다.
- 추가 예상 원가가 없거나 미배분 비용이 있으면 불완전한 전망임을 표시한다.

거래명세서 화면은 원본과 입력표를 나란히 제공한다.
필수 정보를 모르는 경우 초안 저장을 허용하고, 확정에 필요한 검사를 별도로 수행한다.
개인정보·급여·계좌 접근은 사용자 권한으로 제한하며 권한별 상세 범위는 추후 확정한다.

## 5. 주요 데이터 구조와 관계

| 데이터 묶음 | 주요 개체 | 관계·제약 |
|---|---|---|
| 기준정보 | 법인, 대표자, 사용자, 거래처, 계좌, 현장, 비용항목 | 단일 법인에 대표·계좌·현장 복수 |
| 계약·수금 | 공사계약, 변경계약, 수금 일정, 청구, 세금계산서 | 계약·청구·계산서·입금을 분리 연결 |
| 매입 | 거래명세서, 명세서 품목, 매입 배분, 채무, 계산서 연결 | 한 품목을 여러 현장·창고에 배분 |
| 은행·자금 | 가져오기 배치, 은행 거래, 자금 예정, 정산 연결 | 거래와 예정·채권채무 다대다 연결 |
| 인사·급여 | 근로자, 기간별 계약 단가, 출역, 급여 실행, 급여 항목, 지급 연결 | 근무일의 계약 적용, 확정 계산 근거 보존 |
| 어음 | 받을/지급어음, 처리 이력, 할인 내역, 채권채무 연결 | 할인·만기 현금 유입 중복 금지 |
| 재고 | 자재, 장소, 재고 이동, 이동 품목, 원가 배부 | 출발·도착·수량·원가와 원거래 추적 |
| 차량 | 차량, 사용 배정, 정비·지출, 위반·납부 | 고정·공용·본사 사용 및 기간 기록 |
| 세무·문서 | 세무 분류, 추정 실행, 조정, 자료 전달, 첨부, 변경 이력 | 계산 기준 버전·산출 시점·전달본 보관 |

각 거래에는 고유 식별자를 부여한다. 금액·수량은 소수 정밀도를 보장하는 형식으로 저장한다.
내부 계좌이체·취소·정정·환불은 원거래와 연결하며 확정 기록을 단순 삭제하지 않는다.
회계 분개장 전체의 구축 여부와 상세 물리 DB 스키마는 아직 확정하지 않았다.
기술 스택은 Next.js·TypeScript·Tailwind CSS·PostgreSQL·Prisma로 확정했다.
구현 상태와 기술 원칙은 [기술 설계](TECHNICAL-DESIGN.md)를 참조한다.

## 6. 모듈별 예외와 검증

- 은행: 동일 파일 재업로드와 기간 중복을 검사한다. 같은 날짜·금액의 정상 거래를 자동 삭제하지 않는다.
- 은행 양식: 6개 은행별 실제 샘플 확인 후 매핑한다. 현재 가져오기 구현·검증은 미실시다.
- 매입: 품목 배분 합계, 공급가액·부가세·총액을 검사하고 할인·반올림 조정 사유를 기록한다.
- 출역: 같은 날 여러 현장 기록은 합산 공수 검토 대상으로 두고 무조건 차단하지 않는다.
- 급여: 계약 단가 불일치, 공제 중복, 현장 누락을 확인한다. 확정 후 변경은 이력과 재정산 필요.
- 잠정 급여: 자금계획에 추정액을 반영하고 확정 급여로 대체해 이중 계상하지 않는다.
- 어음: 할인하면 기존 만기 입금 예정을 대체한다. 할인료·수수료는 별도 금융비용이다.
- 만기: 월말에 대응 일이 없거나 휴일인 경우 실제 어음·은행 조건을 확인해 저장한다.
- 차량: 공용 비용을 현장에 임의 배분하지 않는다. 보험·자동차세 등의 배분 기준은 별도 결정한다.
- 세무: 부가세 공제/불공제/확인 필요를 구분하고 공급시기·귀속기간을 관리한다.
- 법인세: 누적 실적·연간 전망·재고·감가상각·세무조정·기납부액 등을 반영한다.
- 세율·기한: 사업연도별 기준을 검증해 적용한다. 법인세·법인지방소득세 일반 신고기한과 실제 분납일을 구분한다.
- 세금 적립 목표는 현금 출금이 아니다. 실제 납부 일정만 자금 유출로 반영한다.
- 회계 전달: 정리 중 → 전달 완료 → 보완 요청 → 마감. 전달 후 변경분을 식별한다.

## 7. 기존 파일에서 확인한 사항

급여 파일은 1~8월 38개 시트로 직원 급여·상여·신고/지급 노무대장·현장별 자료가 있다.
1.5·2공수 기록이 있으며, 신고용/지급용 분리 이유는 확인되지 않았다.
상여 시트의 참조 오류 수식 2개와 외부 파일 연결 37개가 확인돼 이관 전에 점검해야 한다.
월별 전체 노무대장과 현장별 자료를 단순 합산하지 않는다.

예산 파일은 예산안 4개와 입금예상 산정근거 시트로 구성돼 있다.
업체 평균 수취일수를 이용한 예상일 계산, 확정/예상 구분, 어음 만기·반복 지출이 있다.
일부 잔액은 고정 숫자이거나 행별 입출금과 연결이 어긋나 있으므로 그대로 이관하지 않는다.
외부 연결은 확인되지 않았다. 원본 파일은 수정하지 않았다.
개인별 급여·주민등록번호·계좌번호와 원본 증빙은 저장소 문서에 복사하지 않는다.

## 8. 개발 순서와 완료 기준

### 1단계: 장부·자금계획의 기반

법인·현장·거래처·계좌·권한, 은행 가져오기, 거래 분류, 수기 채권채무·예정,
부분 정산, 어음, 날짜별 자금 전망을 구현한다.
이 단계에서는 상세 매입·급여 모듈 없이도 기초잔액·미수·미지급·어음·예정을 등록할 수 있어야 한다.

완료 기준:
- 8개 계좌를 별도로 관리하고 기간·파일 중복을 검토할 수 있다.
- 내부이체가 회사 수입·비용을 부풀리지 않는다.
- 1,000만 원 예정에 600만 원 지급 시 미래 예정은 400만 원만 남는다.
- 최종 950만 원 정산 시 원래 예정 1,000만 원과 차이 50만 원이 보존된다.
- 기준 잔액에 반영된 실제 거래와 예정이 중복되지 않는다.
- 어음 할인·만기·결제가 각각 한 번만 현금 흐름에 반영된다.

### 2단계: 품목별 매입·출역·급여·현장 원가

거래명세서와 계산서 대조, 품목별 현장 배분, 계약 단가, 출역표, 월 급여,
현장별 원가·손익을 구현한다. 상세 재고 원장 구축 전에는 미배분·창고 보관분을 분리한다.

완료 기준:
- 명세서·계산서·지급을 연결해 같은 비용을 한 번만 집계한다.
- 여러 현장의 노무비를 한 직원 급여로 합산하고 원가 배분은 유지한다.
- 사무실 월급은 본사 공통비로 집계한다.
- 잠정 금액을 확정 금액으로 대체하며 이력이 남는다.

### 3단계: 재고·차량·세무 자료 확장

창고·현장 재고, 반납·이동, 차량 비용·일정·위반, 세금 추정과 자료 전달을 구현한다.

완료 기준:
- 직납·창고·현장 간 이동 후 수량과 원가를 추적할 수 있다.
- 보험·검사·위반 납부기한과 실제 납부를 관리한다.
- 세금 추정에 기준·미확인 자료·기납부액이 표시되고 최종 신고액과 구분된다.
- 전달 자료와 이후 변경분을 재현할 수 있다.

## 9. 구현 전 확인할 항목

당장 설계를 막지 않는 항목이며 해당 기능 구현 전에 확인한다.

1. 전북은행 실제 사용액(약정 2억 원 확정), 계좌별 별도 관리·사용 제한 자금.
2. 은행별 거래 엑셀 샘플과 회사가 사용할 기초잔액 기준일.
3. 근로계약의 신호수 단가, 공수·수당·공제·보험료·회사 부담분 계산 기준.
4. 과거 신고용/지급용 노무대장의 차이와 실제 은행 지급 대조.
5. 재고 평가 방법·현장 사용 확인 방식·기초재고 수량과 금액.
6. 공용 차량·장기 보험료 등의 비용 배분 기준.
7. 회계사무소의 자료 양식, 세금 추정·세무조정 검토 기준.
8. 사용자 수, 권한, 첨부 보관·백업·마감 후 정정 정책.
9. 회사 전체 회계 손익 산출을 위한 수익 인식·공사 진행 기준.

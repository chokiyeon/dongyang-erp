# 윈도우 설치 EXE · 0.2.3

현재 회사 메인 PC처럼 Node.js 24·npm·PostgreSQL 17·ERP 전용 DB와 회사 설정이 준비된 환경을 대상으로 한다. 프로그램 파일을 직접 복사하지 않고 downloads/ERP.exe를 실행한다. 프로그램은 현재 사용자의 LocalAppData/DongyangERP 전용 폴더에 설치된다.

설치기는 실제 바탕화면과 리디렉션된 바탕화면의 두 단계 하위 폴더에서 기존 ERP 설정을 찾는다. 후보가 하나면 설정을 보존해 가져오고, 설치 폴더에 이미 설정이 있으면 덮어쓰지 않는다. 찾지 못하거나 후보가 여러 개면 ERP DB 암호와 원하는 로그인 비밀번호(8자 이상), 확인 입력을 받는 창을 연다. DB는 기존 erp / dongyang_erp를 사용하며 새로 만들거나 초기화하지 않는다.

실행 중인 ERP가 설치 포트를 쓰는 경우 프로세스 종류와 실제 로그인 페이지를 확인한 다음 종료 여부를 묻는다. 다른 프로그램은 임의 종료하지 않는다. 사용자가 진행 중인 업무를 저장하고 종료를 승인해야 설치를 진행한다.

구성요소 설치 → 기존 ERP DB인지 확인 → DB 백업 → 추가 마이그레이션 → 실행용 빌드 → 서버 준비 확인 → 바탕화면 아이콘을 순서대로 처리한다. 백업 실패·알 수 없는 DB·빌드 실패 시 다음 단계를 진행하지 않는다. DB 초기화나 자동 복원을 하지 않는다. 인터넷이 필요하며 몇 분 걸릴 수 있다. Node.js/PostgreSQL 자체를 새로 설치하는 통합 패키지는 아니다.

설치 후 바탕화면의 동양계전 ERP 아이콘을 사용한다. 회사 사업자등록증 정보는 기준정보 → 회사 정보에서 입력한다. 경리 PC 접속은 메인 PC 시작 메뉴의 동양계전 ERP → 사내 접속 설정에서 실제 메인 IP 192.168.0.12를 설정하고 서버를 다시 켠 뒤 사용한다. 이 설정만 필요한 방화벽/UAC 절차를 거치며 일반 실행기는 방화벽을 바꾸지 않는다.

경리 PC에는 downloads/Client.exe만 실행하면 연결 아이콘을 만든다. Node.js·DB·회사 비밀번호 설정을 복사하지 않는다. 메인 PC의 ERP가 켜져 있고 사내 접근이 허용돼 있어야 한다.

실패하면 바탕화면 ERP-install.log를 자동으로 연다. PowerShell 실행 전부터 설치 경로와 종료 코드를 기록한다. 세부 오류 기록은 설치 폴더의 logs/setup.log와 setup-result.log에 남는다. DB 접속 URL·관리자 암호·세션 키는 로그에서 마스킹한다. 업데이트 전 DB 백업은 backups/install에 새 이름으로 저장한다. Windows 앱 목록의 제거 기능은 바로가기·앱 등록만 해제하며 실제 DB와 설정·백업은 삭제하지 않는다.

NSIS에서 실제 Windows PE 설치 파일로 컴파일했다. 자동 백업·중단·설정 보존·비밀값 마스킹 등의 로직 검증과 PE 형식 검증은 수행했으나, Windows GUI 설치·UAC·실제 파일 이관·네트워크 연결은 회사 PC 실행 확인이 남아 있다. 디지털 코드 서명은 적용하지 않았다. 검사 통과를 모든 회사 PC에서 오류가 없다는 의미로 안내하지 않는다.

재현 빌드: NSIS 3.11 이상으로 scripts/build-windows-installers.py를 실행한다. 설치기에 로컬 .env.office/ERP-login.txt/DB/업로드 자료/로그/기존 EXE를 넣지 않으며 공개 소스 파일 목록을 포함한다. downloads/SHA256.txt로 생성 파일 무결성을 대조할 수 있다.

0.2.3: EXE 압축 해제 파일의 SHA-256과 필수 화면 소스를 DB 변경 전에 대조한다. 빌드 뒤 로그인·상태 확인·설정·근무자료 입력 화면이 app-paths-manifest에 존재하는지 확인한다. 404만 생성된 빌드는 실패 처리한다. 일반 HTTP 500은 포트 충돌로 단정하지 않으며, 자기 설치가 시작한 서버는 저장 PID·실행 파일·실행 경로·포트를 대조해 사용자 확인 후 종료할 수 있다. PowerShell은 Node 출력의 UTF-8을 명시해 한글 진단의 손상을 막는다.

# 시범 운영 시작 기준

전체 경리 업무를 한 번에 전환하지 않고 기존 엑셀을 유지한 채 한 통장·한 공사·한 급여월부터 병행 확인한다. 실제 회사 PC 설치/백업 복구/원본 대조가 끝나기 전에는 운영 준비 완료라고 판단하지 않는다.

## 현재 확인된 준비

- 회사 메인 PC에서 Node.js 24.22.2 실행은 사용자 화면으로 확인했다.
- PostgreSQL 설치는 사용자가 어려움을 겪은 뒤 시험을 보류했다. 회사 전용 DB 생성·ERP 설치·로그인은 아직 미확인이다.
- 원본 NAS 경로는 `\\192.168.0.250\work\동양계전ERP`이고 통장 입출금·급여대장이 준비되어 있다. 회사 실행 계정의 실제 읽기/백업 쓰기·복원 시험은 미실행이다.
- 앱/실시간 PostgreSQL은 메인 PC에, NAS는 원본과 완성 백업에 사용한다. 실시간 DB를 NAS 공유 폴더에 두지 않는다.

## 설치·첫 실행

1. 최신 개발 브랜치 소스를 메인 PC의 별도 폴더에 모두 풀고 `ERP-check.cmd`로 필요한 항목을 확인한다. 단일 EXE 설치 프로그램이 아니며 Node.js 24·PostgreSQL 17 64비트가 필요하다.
2. ERP 전용 계정/빈 DB, `.env.office`를 회사 PC 안에서 준비한다. 비밀번호를 채팅/저장소에 올리지 않는다. 기존 다른 프로그램 DB를 재사용하지 않는다.
3. `ERP-install.cmd`로 의존성·추가 마이그레이션·빌드를 준비한다. 성공하면 `ERP-start.cmd`를 켜고 메인 PC의 `http://127.0.0.1:3000`에 접속한다.
4. 설치 파일은 방화벽·공유기·NAS 자료를 자동 변경하지 않는다. 우선 메인 PC 단독으로 시험하고 사내 다른 PC 접속은 이후 확인한다.

자세한 환경 설정은 OFFICE-PC-AND-NAS.md를 따른다. 체크 스크립트 자체는 Windows 실기 검증 전이며 실제 성공 메시지와 업무 기능 시험이 필요하다.

## 작은 범위 검증

- 통장: 선택한 통장 한 달의 건수·입금/출금·잔액을 은행 원본과 대조하고 통장 간 이체가 회사 비용으로 중복되지 않는지 확인한다. 약정 한도는 현금 잔액에 더하지 않는다.
- 공사: 한 공사의 예산·매입·은행 일부/전액 지급·미지급·발생원가를 원본과 비교한다. 같은 자재비를 청구/현금/원가 배부로 여러 번 더하지 않는다.
- 급여: 해당 월 근로자 한 명의 공수·단가·수당·공제·실지급액을 기존 대장과 비교하고 JPG·A4 한 쪽·엑셀 출력이 맞는지 확인한다. 상용/일용 양식을 구분한다.
- 송금: 송금 준비표의 공사·거래처·확인한 계좌·금액을 원본과 비교한다. 실제 은행 송금이나 문자 발송을 자동 수행하지 않는다.
- 자료 이관: 매입매출 원본 검토 및 기존 ERP 승인번호 대조는 검토 기능이다. 원본 수정/음수 거래를 현재 양수 문서로 임의 등록하지 않는다. 기존 ERP에 승인번호가 없는 자료는 번호 대조만으로 중복 없음이 확인되지 않는다.
- 보존: 로컬 백업과 별도 빈 DB 복원, NAS 검증 복사까지 실제 회사 장비에서 확인한다. 원본 엑셀은 계속 보관한다.

건수·금액·저장·출력·복원 중 하나라도 맞지 않으면 해당 범위의 실제 업무 전환을 보류하고 엑셀을 유지한다. 실제 검증 결과를 확인한 뒤 범위를 넓힌다. 회사 PC는 켜져 있어야 접속할 수 있다.

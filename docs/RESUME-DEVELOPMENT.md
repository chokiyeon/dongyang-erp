# 개발 재개 기록

## 사용자 목표와 진행 원칙

- 경리 업무 전체 개발을 계속하고, 경리가 마무리된 뒤 공무 전용 업무를 개발한다. 작은 기능 완료마다 전체가 끝난 것으로 보고하지 않는다.
- 중단 뒤에는 이 문서와 Git 이력, 실제 코드·검증 결과를 확인해 이어서 진행한다. 크레딧 복구를 감지해 새 작업을 자동 시작하는 기능은 제공되지 않는다. 사용자 재개 메시지가 필요하다.
- 서버 구매·클라우드 임대 없이 회사 메인 PC와 NAS를 우선 활용한다. 실제 설치는 사용자가 진행한다.

## 확인된 회사 운영 구상

- 메인 PC: 윈도우 10, RAM 8GB. 인터넷 팩스와 함께 운영할 후보이며 메모리 증설 가능. CPU·저장공간·윈도우 64비트 여부와 팩스 동시 부하는 설치 전 확인한다.
- NAS: 사용자 사진상 ipTIME NAS2dual, 듀얼코어 1.6GHz·RAM 2GB. 항상 켜져 있으며 기존 회사 자료가 보관돼 있다. 앱/실시간 DB는 메인 PC, NAS는 백업용으로 준비한다.
- 실제 NAS 공유 경로는 사용자가 다음 회사 방문 때 알려주기로 했다. 회사 장치에 접속·설치하거나 NAS 자료를 변경한 상태가 아니다.
- PC가 꺼지면 회사 ERP 접속도 중단된다. 클라우드 개발 실행과 회사 ERP 운영은 별개다.

## 현재 개발 브랜치

`codex/construction-erp-20261031`. main 병합이나 운영 배포는 하지 않았다. 비밀 설정·실제 첨부 원본·DB 덤프는 Git에 포함하지 않는다.

## 최근 추가 구현

- 매입·매출 ↔ 예산안 연결, 은행 일부/전액 처리·해제 동시 반영, 기존 은행 실적 승계. 실제 금액·일자·요청 ID를 보존한다.
- 신고 급여·일수와 회사 부담 보험료/퇴직급여 원가 별도 보관, 총노무원가 제안·배부 재검토.
- 통장별 월초/월말 잔액 대조와 순잔액 반영, 대출 한도 제외, 원본 변경 후 예산안 계산 보류.
- 앱 저장 단계의 월마감·사유 재개방. 마감월과 이전 기간 보호, 이후 열린 월 정상 수금/지급 허용. DB 관리자 직접 변경까지 차단하는 DB 전역 트리거 방식은 사용하지 않는다.
- 공사별 착수금·중도금·잔금·준공 정산 일정, 은행 실적을 보존한 날짜/금액 정정.
- 여러 기존 일정을 한 청구로 통합: 이전 일정 종료·원래 실적 소속 보관, 같은 실적을 재사용한다. 현재 집중 검증 단계다.
- 사내 PC 실행 설정과 NAS 검증 백업. 실제 NAS에는 연결하지 않았다.

## 검증 상태와 다음 실행

- 직전 전체 단위/DB 검증 76개 통과. 전체 브라우저 15개 통과, 기존 회사 보존용으로 제외한 예산안/월마감은 독립 임시 DB에서 별도 통과했다.
- NAS/사내 PC 설정 집중 검증 4개 통과. 여러 일정 통합 집중 DB 검증 1개 통과. 최신 통합 코드 lint/typecheck 통과.
- 최신 통합 이후 전체 빌드·회귀 검증과 브라우저 통합 시나리오를 다시 실행해야 한다. 마지막 전체 검증 숫자를 최신 코드 전체 통과로 오인하지 않는다.
- `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`, `npx playwright test`를 변경에 맞게 실행한다. 브라우저 테스트 전에 빌드한다.
- 공유 개발 DB에서 스킵되는 검증은 `node scripts/test-isolated-budget.mjs budget-layout`, `node scripts/test-isolated-budget.mjs period-review`로 별도 빈 DB에서 수행한다. 스크립트는 자신이 만든 임시 DB만 제거한다.
- 일정 통합의 브라우저 검증·금액 불일치·수기 실적/다른 원본 거부·원래 요청 재시도·원래 일정 이력 표시와 취소 복원을 마무리한다.
- 최신 스키마의 `npm run db:check-backup`으로 독립 DB 백업/복구와 첨부 바이트 대조를 재검증한다.
- 회사 설치용 안내와 실행 설정을 검토한다. 실제 Windows 설치·NAS 공유 경로·사내 주소는 회사에서 확인한 뒤 적용한다.
- 실제 은행/급여/송금 자료 이관·대조 및 회사 PC 시험 운영은 미진행이다. 공무 전용 업무도 아직 미개발이다.

## 주의할 구현 연결

- CashSettlement.tradeBankLinkId로 기존 실제 처리액과 청구 은행 연결을 연결한다. 원래 requestId·금액·일자는 수정하지 않는다.
- 일정 통합은 CashPlan.replacedById와 CashSettlement.originPlanId로 원래 소속을 보관한다. 기존 예산안의 실제 처리액/미래 잔액을 중복 합산하지 않도록 원래 일정의 미래 예정을 종료한다.
- 거래처·직원에게 메시지/급여명세서를 자동 발송하거나 은행 송금을 실행하지 않는다. 운영 서버·유료 서비스 개설도 실행하지 않는다.
- 이미 적용한 마이그레이션 파일은 수정하지 않는다. 추가 변경은 새 마이그레이션으로 만들고 실제 적용 체크섬을 보존한다.

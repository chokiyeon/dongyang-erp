# 개발 재개 기록

## 사용자 목표와 진행 원칙

- 사용자가 2026-11-02 세분화 코드표 요청은 다른 채팅용이었다고 정정했다. 별도 산출물은 ERP에 연결/적용하지 않는다. 현재 거래 업무분류/계정 선택 체계는 그 코드표로 바꾸지 않았다. ERP 개발 목표를 계속 진행한다.

- 경리 업무 전체 개발을 계속하고, 경리가 마무리된 뒤 공무 전용 업무를 개발한다. 작은 기능 완료마다 전체가 끝난 것으로 보고하지 않는다.
- 중단 뒤에는 이 문서와 Git 이력, 실제 코드·검증 결과를 확인해 이어서 진행한다. 크레딧 복구를 감지해 새 작업을 자동 시작하는 기능은 제공되지 않는다. 사용자 재개 메시지가 필요하다.
- 서버 구매·클라우드 임대 없이 회사 메인 PC와 NAS를 우선 활용한다. 실제 설치는 사용자가 진행한다.

## 확인된 회사 운영 구상

- 2026-11-02 사용자 재확인: 전북은행 마이너스통장 약정 한도 200,000,000원. 신한은 기존 확인 50,000,000원. 실제 사용액/은행 잔액과 분리하며 기준 현금에 한도를 더하지 않는다. 회사 실제 계좌 등록 때 적용한다. 합성 개발 계좌를 실제 회사 통장으로 간주해 일괄 변경하지 않는다.

- 메인 PC: 윈도우 10, RAM 8GB. 인터넷 팩스와 함께 운영할 후보이며 메모리 증설 가능. CPU·저장공간·윈도우 64비트 여부와 팩스 동시 부하는 설치 전 확인한다.
- NAS: 사용자 사진상 ipTIME NAS2dual, 듀얼코어 1.6GHz·RAM 2GB. 항상 켜져 있으며 기존 회사 자료가 보관돼 있다. 앱/실시간 DB는 메인 PC, NAS는 백업용으로 준비한다.
- 실제 NAS 공유 경로는 사용자가 다음 회사 방문 때 알려주기로 했다. 회사 장치에 접속·설치하거나 NAS 자료를 변경한 상태가 아니다.
- PC가 꺼지면 회사 ERP 접속도 중단된다. 클라우드 개발 실행과 회사 ERP 운영은 별개다.

## 주의할 구현 연결

- CashSettlement.tradeBankLinkId로 기존 실제 처리액과 청구 은행 연결을 연결한다. 원래 requestId·금액·일자는 수정하지 않는다.
- 일정 통합은 CashPlan.replacedById와 CashSettlement.originPlanId로 원래 소속을 보관한다. 기존 예산안의 실제 처리액/미래 잔액을 중복 합산하지 않도록 원래 일정의 미래 예정을 종료한다.
- 거래처·직원에게 메시지/급여명세서를 자동 발송하거나 은행 송금을 실행하지 않는다. 운영 서버·유료 서비스 개설도 실행하지 않는다.
- 이미 적용한 마이그레이션 파일은 수정하지 않는다. 추가 변경은 새 마이그레이션으로 만들고 실제 적용 체크섬을 보존한다.

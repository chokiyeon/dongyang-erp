- 사용자는 개발을 빨리 정리해 시범 운영할 수 있게 요청했다. 새 기능 확장을 줄이고 한 통장·한 공사·한 급여월 병행 시험을 목표로 한다. 시작 기준은 docs/PILOT-START.md에 정리했다. 실제 회사 PostgreSQL 설치·ERP 실행·백업 복원은 미완료이며 완료라고 표현하지 않는다.
- 기존 ERP 승인번호 대조 API/화면을 구현했다. 원본 파일이 아닌 승인번호만 500개씩 보내 인증·동일 출처·요청 크기·회사 범위를 확인한다. 미등록/일치/차이/취소 이력을 구분하고 검토표에 당시 결과와 관리번호를 남긴다. 조회만 하며 문서나 금액·실적을 바꾸지 않는다. 번호가 없는 기존 문서는 중복 없음으로 확정하지 않는다.
- 대량 대조는 승인번호별로 결과를 묶어 행마다 전체 문서 배열을 반복 검색하지 않는다. 실패/파일 변경 시 이전 결과를 초기화한다.
- ERP-check.cmd와 scripts/check-office.mjs로 Windows의 Node.js 24·64비트·PG17 도구·회사 설정·DB 접속·설정 NAS 읽기 접근을 점검하도록 준비했다. 비밀번호를 출력하거나 설정/DB/NAS를 변경하지 않는다. Windows 실기 검증·PostgreSQL 설치/DB 생성·NAS 쓰기와 복원 검증은 별도다. 코드 문법/eslint 검사 통과.
- 전체 단위/DB 104개, 전체 브라우저 22개 통과·기존 회사 자료 보호로 2개 제외했다. 제외한 예산안·마감도 각각 독립 DB에서 통과해 총 24개 업무 흐름을 검증했다. 최종 대량 대조 처리 개선 후 빌드와 해당 브라우저 검사도 통과했다. 로그 /tmp/pilot-match-*.log 및 /tmp/pilot-final-*.log. 스키마는 변경하지 않았다.

## 최신 사용자 범위 정정 — 최우선

사용자는 경리 업무 전체 완성을 계속 개발하라고 지시했으며 시범 운영 준비로 작업 범위를 줄인 것은 잘못된 해석이었다. 시범 운영 준비에서 멈추지 않는다. 공무 업무는 지금 개발할 때가 아니라고 명확히 재확인했으므로 현재 개발에서 제외한다. 경리 미완료 구현·검증을 이어가고 실제 회사 설치/원본 검증과 코드 완료를 구분한다.

## 경리 원본 행 이관 체크포인트

- 매입매출 검토 후보의 선택 행을 거래처/공사/과세 구분/관리번호/기한/사유 확인 후 청구로 등록하는 기능을 구현했다. 서버가 실제 파일을 재파싱하며 클라이언트 금액은 신뢰하지 않는다. 수정/음수/중복/충돌은 아직 보류한다.
- TradeWorkbookFile/TradeWorkbookSource로 회사별 원본 파일 한 번 보관, 원본 시트/행/머리글/셀/요청 지문을 보관한다. 20261102050000_trade_workbook_sources 적용 완료. 적용 마이그레이션 수정 금지.
- 은행 실적/자금계획을 자동 생성하지 않고 원본 확인과 매입세액 공제는 별도로 남긴다. 원본 양식에 추가 필드를 표시하되 수금/결재 원문을 실제 지급과 혼동하지 않게 표시한다. 문서 원본 다운로드·회계 전달 ZIP에 파일 무결성 확인과 보관 원본을 연결했다.
- lint/typecheck/build, 전체 단위/DB 106개, 관련 브라우저 5개(회계 전달, 원본 탭/분류, 실제 이관, 검토표) 통과. 최신 전체 스키마 독립 백업/복구/체크섬·bytea·20자리 금액 검사 통과. 로그 /tmp/accounting-import-*.log.
- 실제 회사 파일 자동 이관은 하지 않았다. 다음은 거래처 사업자번호로 원본 연결 검증을 보완하고 수정·음수 거래 업무를 구현하는 것이다. 공무 개발은 제외한다.

## 경리 사업자 연결·지급 조건 체크포인트

- 거래처 businessNumber 선택 필드와 PartnerIdentityChange를 추가했다. 10자리 형식/전각/하이픈/앞자리 0을 처리하며 등록 상태 조회는 아니다. 원본 없이 기존 값을 채우지 않는다. 20261102060000_partner_business_identity 적용 완료, 수정 금지.
- 사업자번호 전후/사유/버전 이력을 보관하고 기존 번호 변경 시 송금 계좌 확인을 보류한다. 필드 생략 수정은 번호를 유지한다. 동일 번호의 지점 관리 등은 자동 병합하지 않는다.
- 원본 이관은 거래처 번호가 원본 상대방 번호와 일치해야 한다. 기간 잠금 후 거래처 행을 잠가 변경 경합을 막는다. 기존 ERP 대조에도 번호 미등록/차이를 표시한다. 회계 전달본은 현재 번호/원본 번호를 구분해 보관한다.
- 원본 이관에서 거래처별 익월 말일/즉시 지급·지급방법 및 원가 구분/본사 공통 선택을 지원한다. 은행 실적이나 자금계획을 자동 생성하지 않는다. 지급 조건 미입력 시 이전 요청 지문을 보존한다.
- 최신 lint/typecheck/build, 전체 단위/DB 108개, 관련 브라우저 4개(회계 전달, 사업자 변경 이력·송금 보류, 실제 이관, 기존 대조) 통과. 같은 변경의 거래처 전체 화면 브라우저도 직전 실행에서 통과했다. 최신 전체 스키마 백업·독립 복원/체크섬/bytea/20자리 금액 검사 통과. 로그 /tmp/accounting-identity-*.log. 최신 전체 브라우저는 24개 기준 이전 체크포인트이므로 새 기능 이후 전체와 혼동하지 않는다.
- 경리 전체 미완료의 핵심 다음 작업: 수정·음수 매입매출의 원본 연결·채권채무 정산 정책 및 세무/원가/월마감 반영이다. 이미 지급한 원본을 단순 취소하거나 음수를 양수로 바꿔 가져오지 않는다. 회사 PC 설치와 실제 자료 대조는 별도 미완료이며 공무 개발은 제외한다.
